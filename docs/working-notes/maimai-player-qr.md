# 舞萌玩家二维码读取路线

适用范围：后续舞萌功能的只读原型选型。依据为 2026-10-06 在用户手机上的一次官方公众号流程观察；不是持续有效的接口保证，也不代表已有可交付插件。

## 可用于原型的依据

用户手动打开官方“玩家二维码”卡片后，微信页面的无障碍节点曾包含一个 80 位 ASCII 字母数字 MAID 字段；同次屏幕二维码的内容与 `SGWC + MAID` 相符。有限系统日志也曾出现对应二维码图片请求，但日志不构成完整抓包，不能据此断言没有其他网络调用。

没有验证可独立签发二维码的官方接口。未登录 OAuth 入口只能确认会跳转微信授权，不能承诺登录、成绩读取或自动签发。公开项目 [maimai.py](https://github.com/TrueRou/maimai.py)、[UsagiPass](https://github.com/TrueRou/UsagiPass) 与 [MaiQRTool](https://github.com/TesterNaN/MaiQRTool) 可用于理解流程，不能替代设备证据。

## 下一步需要验证

- 以用户主动触发的官方页面为输入，先验证只读无障碍原型在不同微信版本上的字段可见性与稳定性，再决定实现路线。
- 区分已显示凭据的读取与新凭据签发；有界日志只能作补充，不把历史观察当作可调用 API。
- 原型只处理用户自己的当前凭据，不保留原始二维码、MAID、Cookie 或授权参数；无需为此增加第二个 VPN、全局代理或证书拦截。

清理条件：原型完成路线验证后，将必要契约和边界写入对应插件文档，删除本材料；若官方页面或凭据格式改变，应重新观察并替换依据。原始探测脚本、日志和公开源码镜像不作为长期依赖保留。

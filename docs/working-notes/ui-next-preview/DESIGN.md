# 交互预览设计：任务流程与运行状态

日期：2026-09-20。独立 HTML 提案已同步外层主分支 `26f1069`：延续数据任务、抽卡与排序方案及短时读取规则，补齐账号选择保存和获取来源边界。规则依据为 [UI 规范](../../design/ui-guidelines.md)、[数据兼容](../../architecture/data-management.md) 和 [发布约定](../../development/releasing.md)。本提案不代表 Android 应用已经采用这些新布局。

## 数据任务：先确定对象，再决定处理方式

导出、导入、删除共用一套完整页面：**选择内容 → 设置与核对 → 执行结果**。

选择页只保留对象、复选框和必要解释。关键词搜索、来源筛选、只看已选帮助缩小列表；分组复选框和“全选当前”仅操作当前可见结果。隐藏在其他来源或搜索范围之外的选择保留。底部始终显示总选择数和来源数。

第二步提供与任务有关的决定：

- 导出：默认整个所选范围加密，提供仅敏感内容加密、不加密与逐项自定义。密码只在需要时出现。
- 导入：先读取示例文件中的内容，再为选中项目决定合并或替换。不能合并的内容明确说明，核对页汇总替换数量。
- 删除：默认不选任何内容，提供只选缓存的快捷操作。账号与依赖内容联动，最后列出影响并要求确认；返回修改范围后，确认清除。

宽屏增加已选范围摘要，手机使用固定底栏。系统文件选择器取消、失败和返回修改均保留任务上下文。

## 抽卡：账户总览 → 卡池详情 → 原始记录

总览直接比较各卡池，不再用轮播承担选择，也不在同一位置切换隐藏详情。

- 账户摘要显示记录总量、五星数量和已有记录跨度。
- 卡池以统一行结构并列呈现，使用相同字段便于比较。
- 点击一个卡池进入独立详情，展示当前连续抽数、统计与完整五星轨迹；UP、非 UP 和未知可以筛选。
- 月份柱形图和五星统计数字直接进入对应记录范围。图表使用当前合成记录计算，没有随机画图。
- 记录按日期分组，卡池和星级筛选集中在列表上方；单条详情可进入对应卡池。
- 获取来源、账号管理、UIGF 迁移和统计设置沿用相同的视觉层级，并保留完整演示流程。

统计明确以本机记录为范围。当前预览不提供跨用户运气排名，也不验证真实游戏数据或保底算法。

## 排序：在松手之前看见结果

首页和工具页共用排序引擎。排列模式提供明确的手柄和说明，也保留长按进入拖动、原位移动菜单等方式。

1. 提起：浮动副本略微放大并增加阴影，原布局中保留占位。
2. 移动：占位即时插入新位置，周围卡片平滑让位；靠近上下边缘时持续自动滚动。
3. 放下：浮动副本移动到最终位置，再恢复普通卡片；提供撤销。
4. 取消：Esc、指针取消或在内容区外松手，恢复原顺序。

动画使用浏览器原生 Web Animations 与 FLIP 位移，不引入依赖。指针跟随、布局顺序与动画相互分离；缩放换算统一复用预览的坐标工具。键盘方向键、移动菜单和指针拖动使用同一个顺序模型，隐藏项保留位置。后台任务继续运行，结构更新延后到拖动结束，避免进度刷新打断手势。连接状态是例外：直接更新原卡片及浮动副本中的状态文字，不等拖动结束才清除失效状态。系统减少动态效果偏好会取消动画时长。

## 加载、账号与页面生命周期

**短时读取不增加中间态。** 普通演示去掉固定等待，在样例就绪后直接呈现内容。首次进入数据插件只保留宿主外壳，账号、页签、业务操作和正文一起出现；移除临时 RKS 摘要、骨架和“读取完成后显示内容”等过渡文案。已有内容在刷新时继续保留；新内容或失败提示就绪后再更新。

既有的局部进度保留固定布局位置，200 ms 后才显示；工具外壳的提示从首个可绘制帧等待 500 ms。二者使用 200 ms 渐入，但完成和失败立即取消，无最短展示时长。预览的计时是行为演示，不能替代代表性设备、数据量和冷 / 热启动实测，也不是新增提示的依据。

审阅面板将本地读取、工具外壳启动和账号选择保存的阶段、耗时、结果分开，提供正常、快速、阈值两侧、慢速、失败及手动停留。逐帧记录放在设备画布外，仅记录状态、控件数量、透明度与耗时，不采集输入文本。帧采样最多持续 4 秒、保存 240 条帧明细，避免无限保存历史；长时间手动停留会明确标记截断。

Phigros 首次读取必要成绩后完整呈现总览，定数表按需读取。云存档仍仅手动同步，凭据仅在明确使用时读取。推分结果按档案隔离，切换取消旧读取，更新插件时使旧缓存失效；计算中、失败与结果放在对应 ACC 字段。正常计算和缓存命中不再占用额外状态卡，错误和缓存保存失败仍给出就地处理入口。图片保存等待结果就绪。

抽卡按游戏读取，选择器保留全部已知账号及 UID，未知数量不显示为零。目标账号就绪前，原账号及其记录始终一致，包括等待期间切换页签。目标记录读取完成后，先准备候选账号及统计，等账号选择保存成功再统一更换。保存等待、失败、取消或冷启动都不会提前更新当前账号与设置；等待时可以浏览原账号，修改操作暂不可用。记录失败按游戏隔离，另一游戏和不依赖该记录的获取入口仍能使用。数据页等当前范围内的游戏读取全部结束后报告结果，保留单独重试。米游社来源未读完登录状态前不显示未登录或扫码入口。

设备日志默认查询系统仍保留的全部时间，可缩小到 5 分钟、30 分钟、2 小时或 24 小时。页面明确支持游戏或云游戏 App 的日志，浏览器云游戏网页版不支持；不提供不能回传抽卡链接的网页入口。

首页系统状态占位是既有明确约束：固定卡片位置，连接重新确认，首次启动层最多等待 150 ms。最近两个插件页面继续保留页签、筛选、展开与滚动；释放、停用、更新及模拟冷启动清除临时页面状态，保留账号选择和业务记录。

## 发布与兼容边界

发布中心仅显示正式最新版本和正式历史版本。构建类型是画布外的测试条件，不作为产品中的用户开关。本地 Debug 构建只提供本地开发说明，没有自动/手动远端应用更新；插件仍使用正式发布目录。正式构建把应用与插件更新分为独立设置。

本地安装演示包含单独的 API 1 `plugin.apk` 阻断状态，不能通过普通兼容确认绕过。旧迁移包只列出样例中可识别的宿主状态，不恢复旧可执行载荷和未迁移的 API 1 私有数据，也不继承旧 Shizuku 标记来启用新的可信 Provider。未知备份格式直接拒绝。默认导出保留已安装的 v3 插件包，因为其中可能包含无法从远端恢复的本地版本。

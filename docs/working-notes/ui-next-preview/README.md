## 打开

用现代浏览器直接打开 [完整预览](../ui-next-preview.html)。旧地址 [docs/ui-next-preview.html](../../ui-next-preview.html) 继续提供相同的完整文件，不依赖跳转。可以只复制这个文件到另一台电脑；样式、脚本、图标和合成数据全部内嵌，查看不需要 Codex、Node.js、服务器、CDN 或网络。

## 设计重点

- **数据选择**：导入、导出、删除共用搜索、来源筛选、只看已选、分组选择和固定汇总。批量操作作用于当前结果，其他范围的选择保留。下一步才设置加密、合并、替换或删除确认。
- **抽卡分析**：账户总览并列比较所有卡池，点击进入独立卡池详情。月份图、五星统计和卡池入口可进入对应原始记录，再返回原上下文。记录按日期分组；获取、账号管理、UIGF 迁移与统计设置提供配套页面。
- **排序**：首页和工具页增加排列入口、拖动手柄、浮动副本、实时占位、周围卡片让位、边缘自动滚动和落下动画。支持撤销、Esc 取消、方向键移动与原位移动菜单。后台任务的页面更新不会打断拖动。

可从左侧场景直接开始，也可在应用画布内连续操作。切换场景会建立新的演示状态；应用内部导航保留操作。设计参考和方案取舍见 [DESIGN.md](DESIGN.md)，检查证据见 [VALIDATION.md](VALIDATION.md)。

## 完整覆盖范围

77 个场景覆盖主应用、四个现有插件、数据与任务以及边界状态：

- 主应用：首页、工具、插件已安装/发现、统一详情、权限、版本、设置、关于及许可。
- 数据任务：来源选择、依赖联动、文件选择、加密、合并/替换、删除确认、退出保护、执行、失败及重试。
- Phigros：总览与 RKS 趋势、Clear/FC/AP、完整 B30、全部成绩筛选、历史、定数表、账号与图片预览。
- 抽卡：账户看板、卡池对比、月份统计、卡池详情、记录、获取来源、账号、UIGF 导入导出、统计草稿。
- Shizuku：已连接、未运行、待授权与回到原任务。
- 无障碍：独立的收藏、启用和自动恢复控件、搜索与状态筛选。
- 运行状态：首读与错误、账号选择保存等待/失败、双游戏读取的部分失败、推分计算与缓存失败、本地 Debug 更新限制、旧插件与未知备份版本。
- 过渡审阅：快速完成、200 / 500 ms 提示阈值前后、慢速完成和工具打开失败。
- 其他：正式发布中心、首次使用、空数据、离线、权限不足、部分成功和设计说明。

## 手机比例与操作

手机固定为 **412 × 916**，小屏为 **360 × 800**，宽屏为 **960 × 720**。手机比例约 20:9。这些逻辑尺寸用于审阅布局，不代表本次实测的设备密度或系统字体大小。

“适应窗口”将整台设备等比缩放，不改变内部布局。100% 按原始 CSS 逻辑尺寸显示，超出窗口时可滚动；它不表示显示器上的物理尺寸与真机相同。也可选择 75%、125% 或“专注预览”。不提供独立大字号模式。

普通点击打开工具。进入“排列”后，可直接拖动或使用方向键排序；长按也能提起卡片。右键、Shift+F10 或排列模式中的单击可打开移动菜单。Esc 优先取消本次拖动，其次退出排列模式或关闭当前浮层。系统减少动态效果偏好会取消排序动画时长。

## 加载与生命周期审阅

正常打开不人为等待：样例读取在微任务中完成，没有原来固定的 650 ms 延迟。首次进入先保留稳定外壳，账号栏、页签、业务按钮和正文就绪后一起出现；不先展示骨架、临时 RKS 摘要、零记录或扫码入口。

右侧控制下一次模拟操作的**阶段、耗时、结果**，使用后恢复“直接完成”。阶段包括工具外壳启动、插件本地内容和账号选择保存；可以选择 80 ms、提示阈值前后、1200 ms 或手动停留。耗时只是审阅条件，不是真机数据，也不能证明产品需要新增加载中间态。

- 本地读取复用固定位置进度条：200 ms 后仍未完成才渐入，完成或失败立即结束。外壳启动单独从可绘制帧开始等待 500 ms，两者均按既有规范使用 200 ms 渐入，不延迟最终内容。
- “本次过渡记录”采样最多 4 秒的浏览器绘制帧（最多保存 240 条明细），记录内容是否提前出现、刷新是否变空、提示透明度与完成时间。它是 DOM / CSS 帧采样，不是 Android 录屏或性能测量。
- Phigros 和抽卡标准页顶栏提供“刷新本地数据”。慢刷新保留原内容、已展开项、筛选与滚动；失败保留可用内容并显示重试。
- Phigros 仍仅手动同步云存档。推分计算放在对应 ACC 字段，计算完成只更新数值；不再为正常计算或缓存命中单独占用整块状态区。失败、缓存保存失败和图片保存门槛继续保留。
- 抽卡按游戏读取，记录读取完成后还需保存账号选择，保存成功才统一更新账号、设置和统计；等待及保存失败期间，跨页仍使用原账号，冲突写入暂不可用。取消或模拟冷启动会取消尚未完成的选择。失败按游戏隔离，正常账号和获取来源仍可使用。
- 数据页等待当前范围内各游戏读取结束后统一显示结果，失败游戏单独重试；仍能打开已正常读取的账号。
- 设备日志默认查找系统保留的全部时间，可选 5 分钟、30 分钟、2 小时或 24 小时。说明明确区分游戏 / 云游戏 App 与浏览器云游戏网页版，后者不受支持。
- 首页系统部件保留固定数值位置，首次确认连接时不冒用已连接状态。启动层最多等待 150 ms，之后可使用首页；拖动期间系统状态仍就地更新。
- 最近两个插件保留页签、筛选、展开项与滚动；释放后重新进入默认总览。“模拟冷启动”保留业务样例、账号选择、设置与任务，清除临时页面状态。
- 构建类型只在审阅面板切换。本地 Debug 无远端应用更新，插件仍使用正式目录。

本轮行为依据已同步的 [UI 规范](../../design/ui-guidelines.md)。外层主分支仍锁定自己的子模块组合；预览按规范表达交互，不自行提升组件集成版本。

## 演示边界

账号、记录、统计、曲目定数、文件、版本和任务全部是合成样例，不作为真实游戏数据或算法验证依据。

二维码不能登录；文件选择器是内置演示。预览不读取真实备份、不请求网络、不授予 Android 权限，也不修改应用。CSP 禁止网络连接。研究链接只有手动打开时才会访问站点。

“电池观察”是用于安装流程的虚构条目。图片保存会生成带 UI PREVIEW 标记的示例 SVG；其他保存、导入、删除和插件操作只改变本次预览状态，不生成正式备份或插件包。

## 开发与生成

使用本机已有 Node.js，无第三方依赖：

```powershell
node docs/working-notes/ui-next-preview/build.mjs
```

生成器检查合并 JavaScript 的语法，同时生成 `docs/working-notes/ui-next-preview.html` 与 `docs/ui-next-preview.html`，两个文件内容完全一致。旧的 `node docs/ui-next-preview/build.mjs` 命令仍可使用。输出采用经典内嵌脚本，没有模块加载或跨文件请求。

可选开发服务只暴露这一个预览文件，绑定随机回环端口：

```powershell
node docs/working-notes/ui-next-preview/serve.mjs
```

终端显示地址，Ctrl+C 退出。该服务不是交付文件的运行依赖。

| 源文件 | 作用 |
| --- | --- |
| `data.js` | 图标、数据、场景、说明和初始状态 |
| `viewport.js` | 固定画布、等比缩放和坐标转换 |
| `core.js` | 公共组件、导航、数据选择模型与任务状态 |
| `runtime-preview.js` | 可取消的异步读取、两页缓存、冷启动、账号隔离及推分状态 |
| `host.js` | 首页、工具、插件、设置及任务页面 |
| `data-flow.js` | 三类数据任务的共享选择与核对界面 |
| `sorting.js` | 共用拖动、让位、落下、自动滚动和撤销 |
| `phigros.js` | Phigros 页面 |
| `gacha.js` | 抽卡页面与统计视图 |
| `system.js` | 系统插件、发布中心和指南 |
| `overlays.js` | 对象菜单、选择器和确认浮层 |
| `actions.js` | 操作分发、键盘和演示任务入口 |
| `styles.css` / `redesign.css` / `runtime-preview.css` | 共用样式、第三轮设计与运行状态样式 |

外部项目只作为设计参考，没有引入其运行时代码、字体或图片。

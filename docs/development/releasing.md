# 分支与发布

外层工作区及六个组件仓库均以 `main` 为主分支。组件日常开发可以直接在各自的 `main` 上进行；需要隔离并行工作或单独评审时，再按需创建 `codex/*` 分支，不要求长期维护固定用途的开发分支。提交到 `main` 不等于发布，正式版由显式版本标签触发。

历史存档分支不参与日常集成，清理时按其保留目的单独判断。保留含未提交修改的工作树；删除工作树前检查其自身和全部嵌套仓库。组件分支独立管理，外层 gitlink 只在组件已经验证、提交并可从远端获取后更新。

外层 `main` 维护已验证的组件集成组合；单组件日常开发仍在对应仓库进行，不因直接使用组件 `main` 就同步更新外层 gitlink。

## 本地调试

组件 `ci.yml` 验证并上传 Actions 构建产物，不创建 Release。Debug 仅用于本地构建、模拟器和 ADB 实体设备调试；不维护远程 Debug 工作流、标签或调试目录。

跨仓库联调从工作区根目录执行：

```powershell
.\tools\build-all.ps1
.\tools\install-latest.ps1 -Serial <设备序列号>
```

单组件开发使用对应仓库的构建命令，只安装本次重新构建的产物。插件可通过 Debug ADB 入口同版本原子替换；本地构建和安装不算发布，不必为每次调试提升版本。

## 正式版与 SDK

正式发布继续手动推送 `v<versionName>`，必须匹配构建版本。SDK 的 `plugin-sdk-v<version>` 标签标识相应 SDK 源码，供可信 Provider 的正式构建引用，不应触发应用发布。发布前核对版本、versionCode 与 CHANGELOG；Debug、预发布、正式发布均算发布。外层工作区不额外复制组件 Release。

正式发布完成后，各组件通过 GitHub App 向 `plugin-registry` 发送更新事件，由索引工作流生成并签名正式最新索引与历史目录。若通知失败，可手动运行该仓库的 `pages.yml`，无需重新创建 Release。

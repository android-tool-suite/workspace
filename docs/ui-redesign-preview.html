01 · PRINCIPLES

先统一判断方式，再统一外观

页面职责、信息层级和反馈强度优先于装饰。所有插件共享同一套外壳，领域数据仍可保留自己的表达。

01

按用户意图分区

主页看状态，工具负责进入，管理调行为，仓库管安装与版本，设置承载全局偏好。

02

摘要先于展开

收起态也要交代关键状态。低频动作进入展开区、溢出菜单或底部面板。

03

主动操作有反馈

Snackbar、局部进度和可重试错误跟着对象出现；后台无结果不制造噪音。

04

用户语言优先

说明状态、下一步和后果，不把宿主、versionCode、索引签名等实现术语放进常规界面。

03 · LAYOUT

一级页面不重复顶栏

手机使用五项底栏，宽度达到 840 dp 后切换为侧栏；内容最大 720 dp。插件详情与关于才使用返回顶栏。

手机

五个入口固定顺序：主页、工具、管理、仓库、设置。一级内容直接从标题、说明或分段开始。

内容 · 20 dp 水平边距

宽屏

07 · INTERACTION

保留现行长按编辑方式

点按、长按菜单和长按拖动共用同一对象，但按是否发生移动区分结果；读屏另有等价自定义动作。

位置点按长按后不移动长按并拖动恢复入口
主页小部件进入所属插件调整尺寸或从主页移除显示落点虚影，松手保存排序分段右侧“添加 N”
工具卡打开工具隐藏、停用或前往管理显示落点虚影，松手保存排序列表末尾“在管理中恢复”
管理卡整行展开／收起；Switch 独立操作无额外语义不支持拖动展开区直接修改显示状态
不采用旧版编辑态显式编辑模式、常驻拖拽手柄、左上角移除标记、撤销栈、尺寸缩略图 sheet 和工具编辑态可见性开关，不属于当前设计基线，也不再作为后续待办。
08 · COPY & REVIEW

写状态、下一步和后果

安全与数据范围需要保留，但要使用用户理解的结果语言，不用架构自述替代说明。

避免推荐原因
要求宿主 versionCode ≥ 18需要应用 1.5.0 或更高版本版本可理解，也能直接给“更新应用”
3 个内置 · 1 个外部4 个工具已就绪不暴露实现分类
仓库索引签名验证成功已验证发布展示结果，不展示机制
操作失败仓库刷新失败：网络连接超时说明失败对象与原因
确定删除插件／全部更新／重新安装按钮直接表达后果

应该

✓复用 SDK token、共享组件和成对语义色。
✓为空、加载、失败、禁用和处理中状态提供明确设计。
✓让整行、Switch、菜单和读屏动作都能独立操作。
✓同时检查浅色、深色、动态取色、手机与宽屏。

不要

×复制一套近似颜色、8/18/20/22 dp 卡片圆角或浅色专用组件。
×给每个设置行加装饰图标，或把普通版本号做成伪按钮。
×用 Toast 或常驻横幅承载需要阅读、重试或仅短暂存在的结果。
×把旧预览中的四项底栏、全局顶栏或显式编辑态重新当成规范。

# ATS 发布平台计划

状态：P2 方向基线（低于 Runtime v2 和 AI 开发，高于跨平台）
更新日期：2026-08-20
前置条件：Runtime v2 包签名／来源证明稳定；AI 草稿流能产出可审查、可复现的构建

## 1. 目标

建立可自托管的 ATS 插件发布与发现服务，同时保留 GitHub 作为源码、CI 或制品镜像适配器。平台管理发布元数据和不可变对象，不把某个 Git 托管商的 Release 数据结构当成长期领域模型。

当前 `plugin-registry` 的签名索引、Debug/Release 渠道和 Pages 页面继续运行，直到新平台完成签名兼容、回滚和迁移验证。

## 2. 对象模型

- SourceSnapshot：不可变源码快照，记录内容摘要、依赖锁和来源。
- BuildRecord：工具链、输入摘要、构建日志摘要、测试与来源证明。
- Artifact：内容寻址的 `.atsplugin` 或 Provider 制品，不可原地覆盖。
- Release：把插件 ID、版本、渠道、Artifact 和兼容范围绑定起来的签名记录。
- Draft：尚未公开、可反复替换候选构建的工作区；每个候选 Artifact 仍不可变。
- Publisher：签名身份、密钥轮换、恢复和撤销状态。
- Visibility：`private`、`unlisted`、`public`，与 Release 渠道正交。

同一摘要只存一份逻辑对象；版本号不得指向变化后的字节。撤回通过新的状态记录完成，不删除历史签名证据。

## 3. GitHub Adapter

GitHub Adapter 可以：

- 从指定提交创建 SourceSnapshot；
- 读取 CI 结果和来源证明；
- 导入或镜像 Release Artifact；
- 把 ATS Release 状态同步回仓库。

平台核心也必须支持不依赖 GitHub 的上传、构建器和对象存储。Adapter 失败不能改变已发布 Artifact 的可用性或摘要。

## 4. 分阶段可见性

### P2.1 私有草稿

- 仅发布者和受邀测试者可见；
- 接收手工构建或 Developer Agent 批准后的候选；
- 展示权限、Dataset、后台任务、测试和来源证明差异；
- 允许安装到 Debug／草稿渠道，不进入公共搜索。

### P2.2 Unlisted 发布

- 持链接可访问，不进入推荐和全文搜索；
- 用于小范围共享、组织内工具和发布流程演练；
- 支持签名撤销、版本回退、兼容性拦截和安全通知。

### P2.3 公共社区

- 搜索、分类、收藏、版本历史和兼容性展示；
- 发布者身份与签名状态可见；
- 举报、下架、申诉、恶意制品隔离和审计日志形成闭环；
- 推荐系统不能覆盖签名、兼容性或用户明确渠道选择。

## 5. 构建与供应链

- 构建器使用固定镜像和无长期凭据的短期任务环境。
- SourceSnapshot、依赖锁和构建配置共同决定 BuildRecord。
- Artifact 发布前执行 schema、路径、大小、签名、恶意载荷与 Capability 策略检查。
- 发布记录包含 SHA-256、签名、来源证明、SDK/Runtime 兼容范围和测试摘要。
- 私钥不进入 Developer Agent、插件构建容器或普通管理员会话；支持密钥轮换和吊销。

## 6. 与 Runtime v2 的边界

Runtime v2 定义包、签名覆盖范围、兼容解析和客户端安装事务；发布平台只消费这些稳定契约。平台的社交、审核、推荐或计费需求不得反向加入插件运行时 RPC。

客户端必须可以安装本地签名包和其他兼容索引，ATS 平台不是唯一强制来源。用户的仓库选择、企业镜像和离线包保持可用。

## 7. 退出条件

- 私有草稿可完成上传／构建、签名、安装、撤回和回滚。
- 相同版本不能替换字节；任意安装均能追溯到不可变 Artifact 与 BuildRecord。
- GitHub Adapter 断开后，已发布版本仍可验证和下载。
- 新旧索引并行期的版本、渠道和签名决策一致。
- 在公开社区启用前，举报、下架、密钥泄露和恶意更新演练均通过。

## 8. 非目标

- P2 首版不实现社交动态、广告、支付或复杂推荐。
- 不把 Developer Agent 的一次模型输出直接视为已审核发布。
- 不在本计划中实现 iOS 分发；未来平台可增加平台特定 Artifact 与审核状态，但不能假定 Android 的动态插件能力在 iOS 可用。

# Android Tool Suite UI 设计模式规范与实现指南

本文定义 Android Tool Suite 宿主应用与插件共同遵循的 UI 设计语言、页面模式和交互规则。

配套样例：[ui-preview.html](ui-preview.html)。HTML 用于查看浅色／深色配色、
核心组件、四个一级页面、插件详情和状态反馈；它是可离线打开的独立本地 HTML，内嵌图标并保留许可，
不依赖 Codex 运行时或在线 CDN。页面中的数据与外部操作均为演示，实际组件与业务状态以代码为准。

## 1. 适用范围与事实来源

本规范适用于：

- 宿主的主页、工具、仓库、设置、数据管理、任务结果、关于和工具详情容器；
- `plugin-sdk` 提供的 Compose 设计系统；
- 无障碍授权、Phigros Data Studio、抽卡分析及后续外部插件；
- 空态、加载态、错误态、拖拽态、弹窗、底部面板和 Snackbar。

发生差异时按以下顺序判断：

1. `app/plugin-sdk/.../SuiteDesignSystem.kt`、`SuiteTokens.kt`、`SuiteSettings.kt`、
   `SuiteStates.kt` 中的公开 token 和组件；
2. `app/app/.../host/` 中的导航、插件中心、数据任务和排序实现；
3. 本文的说明和 HTML 样例。

规范描述的是当前已经采用的设计基线，不把未实施设想写成既定行为。后续若修改基线，应同时
更新 SDK、宿主、受影响插件、本文和预览页。

## 2. 设计原则

### 2.1 按用户意图划分页面

同一动作应有清晰主归属，允许在最贴近上下文的位置提供快捷入口，但不要让多个页面承担完全
相同的主职责。

| 用户意图 | 主归属 | 可接受的快捷入口 |
| --- | --- | --- |
| 查看状态、进入常用能力 | 主页 | 小部件点按进入插件 |
| 浏览和打开全部工具 | 工具 | 长按菜单可隐藏、停用或前往管理 |
| 控制启用、收纳、位置和更新检查 | 工具 → 插件详情 | 每个插件的详情按钮直接进入 |
| 安装、更新、切换版本、导入插件包 | 仓库／版本与来源 | 首页更新入口、已安装列表更新提示 |
| 主题、配色、自动更新 | 设置 | 底部或侧边一级导航 |
| 查看、导出、导入、清理本地内容 | 数据管理 | 设置中的统一入口 |
| 查看正在进行或已结束的操作 | 任务与结果 | 当前操作完成后的结果反馈 |
| 查看构建与许可信息 | 关于 | 设置中的“关于”入口 |

### 2.2 先让状态可扫，再让细节可展开

- 列表首屏优先呈现名称、关键状态和最常用动作。
- 管理列表显示摘要，点按打开该插件的独立详情页；摘要覆盖启用、显示位置和更新检查等重要状态。
- 版本、来源、兼容性和进度放在对应对象附近，不使用全局大横幅代替局部状态。
- 低频操作进入展开区、溢出菜单或底部面板；不要把每项能力都平铺成按钮墙。

### 2.3 一屏只突出一个主动作

- `Button` 表示当前卡片或步骤的主要下一步。
- `OutlinedButton` 表示并列但次要的动作。
- `TextButton` 表示轻量导航、恢复、刷新或关闭。
- 删除、覆盖、降级等高风险动作不得仅靠颜色区分，必须使用明确动词，并在不可逆时确认。

### 2.4 安静地处理后台工作，明确反馈主动操作

- 启动时自动检查：无更新或失败均保持静默；有更新才提示。
- 更新提醒、数量和“全部更新”只包含已安装插件；仓库存在但未安装的项目留在“可安装”列表。
- 启用需要冷启动激活的系统插件时，显示不会自动消失、不能点外部或返回键关闭的确认弹窗，提供“立即重启”“稍后重启”。选择稍后后，管理卡片保留“重启以激活”入口；立即重启应重启当前应用进程。
- 用户主动检查：开始、成功和失败都要有 Snackbar 或就地反馈。
- 下载、导入、安装进度放在对应应用或插件卡片内。
- 可恢复的列表刷新错误使用 `ErrorState` 并提供“重试”。

### 数据加载与页面保留

- **加载中间态默认不添加。** 本地读取、缓存恢复等短时操作优先直接呈现最终内容；读取期间保留已有内容或稳定页面外壳，不为尚未完成的一次异步操作单独增加过渡页面。
- 新增加载页、占位文案、骨架屏或临时摘要前，必须通过代表性设备、数据量以及冷／热启动实测，确认该操作存在持续等待，且提示能帮助用户理解或操作。无法确认长时间加载时，不添加中间态；固定延迟到期本身不是长耗时证据。
- “数据保存在本机”等中性说明如果只在加载期间出现、随后被账号或结果替换，也属于加载中间态。不得用换文案、淡入动画或更短的展示时间掩盖闪烁；有长期价值的说明应放在稳定位置，不临时充当加载占位。未读取完成也不得先显示空数据或零值，再切换到真实内容。
- 确认需要长时间等待时，优先在对应对象内显示进度，并保留可用内容；只有整个页面确实不可用时才考虑独立加载页。内容就绪立即呈现，取消尚未显示的提示，不为播放动画或凑足提示时长而延迟结果；失败及时提示并允许重试。
- 评审不能只看加载页和完成页的静态截图，必须检查两者之间的实际过渡。快速完成、接近提示阈值完成、慢加载及失败都要覆盖；短暂闪过的说明、摘要或整页占位均属于体验缺陷。

宿主与插件的具体约束：

- 已有主页摘要时直接显示，后台刷新不清空卡片；主页不可见时仅标记数据变化，返回后合并刷新；首次无数据时使用稳定标题与数值占位，不闪过旋转动画。
- 摘要按插件包版本和数据代际隔离，数据写入／恢复后失效；撤销权限时立即清除相关展示缓存。
- 系统连接和授权状态不从磁盘恢复为已确认状态，进入前台重新确认。
- 首页可见的系统状态部件在首帧绘制前启动异步读取，首次读取不增加防抖等待；后续连续状态回调仍合并刷新。加载与正常内容使用同一个卡片和标题布局，不切换整张卡片。首次可绘制时保留不透明启动层最多 150 ms，底下首页正常绘制，内容或错误状态完成界面更新后立即淡出启动屏；到期正常显示首页及真实加载状态，不持续等待授权，也不在后续刷新时重新遮盖首页。
- 当前 Activity 保留最近两个插件页面，返回时恢复页面内容、页签与滚动；第三个页面进入后释放最久未使用页面。停用、更新或 Activity 销毁会释放对应页面。
- Phigros 和抽卡分析不将页签、滚动位置持久化；应用重新启动或页面被释放后，首次进入分别从「总览」和「概览」顶部开始。页面存活期间保留位置，刷新不重置当前页；账号选择和业务数据继续保存。
- 两个数据插件首次读取完成后一起呈现账号说明、账号栏、页签、按钮和当前页内容；准备期间不显示临时文字或可交互控件，不用定时器强制放出半成品，也不另加等待时间。刷新保留已有内容。确需展示的进度条保留布局位置，现有反馈采用 200 ms 延迟和 200 ms 渐入；这些参数不构成新增中间态的理由。Phigros 不展示随后被完整成绩替换的临时摘要。
- 宿主的 Web 工具加载提示从 WebView 创建完成后的可绘制帧开始等待 500 ms；提示以 200 ms 渐入，平台初始化阻塞不计入提示延迟，页面就绪或失败即取消等待，不延迟实际内容展示。
- Phigros 只在用户手动同步时更新云存档；进入前台、定时唤醒和打开插件均不自动更新或应用记录。首次进入总览读取本地成绩；成绩与曲库按页加载，登录凭据仅在同步或账号写入时读取。按页读取尚未完成时不提前显示错误或重试，只有失败才提供重试入口。
- 抽卡根页提供游戏切换，账号选择器只显示当前游戏的已知账号及真实 UID；先加载上次所选账号的记录，其他记录在切换对应游戏或账号时加载。账号管理、导入与导出按操作范围补全记录。未加载的数据不显示为零，米游社凭据按获取来源读取。
- 抽卡账号切换在设置保存成功后统一替换选中账号、统计与记录；等待和保存失败期间继续浏览原账号。记录读取失败按游戏隔离，正常账号及不依赖该记录的获取来源仍可使用，失败游戏可单独重试。
- 米游社登录状态未读取完成时，不先显示未登录或扫码入口；读取失败显示错误和重试。账号记录读取失败也不得显示为“没有记录”。
- 推分结果随同步更新并缓存；旧数据首次补算显示“计算中”，成绩仍可浏览，结果到达后只更新对应数值。缓存失效或失败不显示旧账号结果。
- 点击跨页标签只准备起止页，保留横向过渡；手势拖动再准备相邻页，不为途经页提前计算完整列表。
- 失败就地提示并允许重试。

### 2.5 共享外壳，保留领域表达

宿主和插件共享布局密度、圆角、主题、语义色、状态组件和动作层级。游戏稀有度、谱面难度等
领域色可以由插件维护，但必须同时提供浅色／深色方案，并用文字或图标补充语义，不能只靠颜色。

## 3. 信息架构与导航

### 3.1 四个一级入口

手机使用底部导航，宽屏使用侧边导航栏，顺序固定为：主页、工具、仓库、设置。
四个分区可横向滑动，选中态与页面位置同步。工具维护全部已安装插件，保留排序，并为每个插件提供详情按钮；停用插件仍可进入详情。仓库浏览发布目录与导入本地包，详情返回保持来源。

一级页使用简洁顶栏。任务历史的固定入口位于设置；正在执行的操作与完成后的结果可提供上下文反馈，
不在所有顶栏、工具菜单和数据页反复铺设同一个任务入口。设置通过底部或侧边一级导航进入。

### 3.2 子页、工具和返回

插件详情、功能权限、版本与来源、数据管理、任务结果和关于使用标准返回顶栏。
工具和仓库都进入同一对象详情；工具顶栏直接进入插件设置；返回恢复来源分区、标签与滚动上下文。

工具页面由应用绘制顶栏。Web 插件根内容不再添加应用级标题；卡池详情、统计设置、
历史明细和账号面板等内部页面可显示本地上下文及明确返回动作。
系统返回与应用顶栏返回先处理最上层弹窗、未保存修改保护或内部子页，根页才退出工具。
工具顶栏提供直接进入插件设置的图标，不为单个操作设置溢出菜单；内部返回状态不写入持久设置。

### 3.3 响应式边界

- 一级内容最大宽度为 `720 dp`，宽屏时居中。
- 插件详情与权限、版本子页使用最大 `720 dp` 的居中区域；插件身份在详情展示一次，发布者、兼容性、来源和包大小集中到“关于插件”，不在子页复制摘要卡或宽屏侧栏。
- 可用宽度达到 `840 dp` 时，底部导航切换为侧边导航栏。
- 所有分支都必须处理状态栏、导航栏和手势区域 inset。
- 响应式变化只重排导航和可用宽度，不改变功能归属或文案含义。

## 4. 视觉 token

代码中必须使用 `SuiteSpacing`、`SuiteShapes`、`MaterialTheme.colorScheme`、
`SuiteSemantic.current` 和 `MaterialTheme.typography`。下列数值用于设计稿、评审和 HTML 对齐，
业务代码不要复制一套常量。

### 4.1 间距

| Token | 数值 | 常见用途 |
| --- | ---: | --- |
| `xs` | 4 dp | 同一信息组内的紧密间隔 |
| `sm` | 8 dp | 标签、按钮内容、状态信息 |
| `md` | 12 dp | 列表间隔、图标与文字、设置行垂直内边距 |
| `lg` | 16 dp | 内容块间隔、展开区内边距 |
| `xl` | 20 dp | 页面水平边距、卡片主要内边距 |
| `xxl` | 24 dp | 页面垂直边距、较大分组间隔 |
| `xxxl` | 32 dp | 独立大区块间隔 |

默认一级页使用 `20 dp` 水平边距、`24 dp` 垂直边距；卡片列表间隔优先使用 `12 dp`，
跨分段间隔使用 `14–16 dp`。

### 4.2 圆角

| Token | 数值 | 用途 |
| --- | ---: | --- |
| `SuiteShapes.Card` | 24 dp | 主卡片、空态、错误态、重要面板 |
| `SuiteShapes.Inner` | 16 dp | 卡片内区域、图标底座、进度与领域信息块 |
| `SuiteShapes.Chip` | 12 dp | 状态标签、密集图标底座、短选择器 |
| `SuiteShapes.Dialog` | 28 dp | 对话框和高层浮层 |

胶囊按钮、Switch 和进度条可使用完整圆角。不要在业务页面继续引入 8、18、20、22 dp 等
近似但不同的卡片圆角。

### 4.3 品牌色与主题

默认使用应用自带 teal 色板；Android 12 及以上可由用户选择跟随壁纸。主题可跟随系统，也可
固定浅色或深色。插件必须通过 `composePluginView`／`SuiteTheme` 读取宿主选择，不得自行读取
系统主题后覆盖宿主设置。

主要色板：

| 角色 | 浅色 | 深色 |
| --- | --- | --- |
| `primary` | `#006B5F` | `#82D5C6` |
| `primaryContainer` | `#C3E4DC` | `#005047` |
| `secondaryContainer` | `#D5E7E2` | `#334B47` |
| `background` / `surface` | `#F7FAF8` | `#0E1513` |
| `surfaceContainerLow` | `#F0F5F2` | `#151C1A` |
| `surfaceContainer` | `#EAF0ED` | `#1A2220` |
| `surfaceContainerHigh` | `#E3EAE6` | `#252D2A` |
| `surfaceContainerHighest` | `#DCE5E1` | `#303936` |
| `surfaceVariant` | `#DAE5E1` | `#3F4946` |
| `outline` | `#6F7976` | `#89938F` |
| `outlineVariant` | `#BFC9C5` | `#3F4946` |
| `error` | `#BA1A1A` | `#FFB4AB` |

成功、警告、危险和信息必须使用 `SuiteSemantic.current` 的成对前景／容器色：

- 实心语义色使用 `success` + `onSuccess` 等组合；
- 浅底信息块使用 `successContainer` + `onSuccessContainer` 等组合；
- 不要把白字直接放在浅色 warning／success 容器上；
- 已废弃的 `SuiteColors` 和硬编码浅色值不得用于新代码。

### 4.4 字体层级

| 样式 | 使用场景 |
| --- | --- |
| `headlineLarge` | 关键数值等单一视觉重点；一屏通常只出现一次 |
| `headlineSmall` | 关键结果、账号名、核心数值 |
| `titleLarge` | 分段标题、卡片主区标题、底部面板标题 |
| `titleMedium` | 列表卡标题、设置入口名称 |
| `bodyLarge` | 页面主说明 |
| `bodyMedium` | 卡片说明、常规正文 |
| `bodySmall` | 版本、时间、数量、兼容性等元数据 |
| `labelLarge` / `labelMedium` | 分类标记、按钮、短状态 |

使用主题字重，不在每个插件中重复指定相近的字号和粗细。大数值可加粗，但同一卡片内只保留一个
最强视觉焦点。

## 5. 页面骨架与组件模式

### 5.1 页面和分段

- 一级长页面优先使用 `LazyColumn`，保留滚动位置。
- 页面首部只在确实需要身份或摘要时使用大标题；工具、管理、仓库、设置可直接进入说明或分段。
- 分段使用 `SectionHeader(title, subtitle, action)`。副标题负责数量或上下文，右侧动作只放
  “刷新”“全部更新”“添加”等和整个分段有关的操作。
- 不用卡片包住整个页面，也不用卡片包住每个设置分组。

### 5.2 卡片

普通内容优先使用 `SuiteCard`：

- 默认 `surfaceContainerLow`、无阴影、`24 dp` 圆角；
- 内部水平 `20 dp`、垂直 `18 dp`，内容间隔 `8 dp`；
- 标题后接说明、状态或动作，不塞入与对象无关的全局信息；
- 强调摘要可使用 `primaryContainer`，但一屏不要出现多张同等强调卡。

可展开管理卡使用同样的圆角和底色；展开时用 `2 dp primary` 描边建立归属。整行可点按展开，
启用 Switch 保持独立点击目标，多张卡可以同时展开。

### 5.3 图标底座

工具和插件列表使用圆角方形底座统一视觉重量：

- 普通工具卡：`48 dp` 底座、`24 dp` 图标、`Inner` 圆角；
- 密集管理／仓库行：`38 dp` 底座、`20 dp` 图标、`Chip` 圆角；
- 底色 `secondaryContainer`，图标 `onSecondaryContainer`；
- 图标若是卡片上唯一的类型信息，要提供可理解的 `contentDescription`。

### 5.4 设置行

设置页使用 `SuiteSettingsGroup`、`SuiteSettingsRow`、`SuiteSettingsSwitchRow`，不使用卡片堆叠：

- 整行最小触摸区域按 Material 组件保证，标题使用 `bodyLarge`；
- 补充说明使用 `bodySmall`，当前值放右侧；
- 有下拉选择时同时显示当前值和向下箭头；
- “立即检查”等需要反馈当前状态的动作可用 `emphasized = true`；备份与迁移入口保持普通设置行配色；
- 装饰性图标不要给每行都加，只有“关于”等需要对象身份的入口使用图标底座。
- 数据包项目较多时使用“owner 分组 → Dataset 行”的两级展开，不把所有插件摊成一列；分组标题和展开后的 Dataset 行必须位于同一个描边圆角容器中，Dataset 行使用 `surfaceContainerLow` 与 `outlineVariant` 分隔线，不拆成多张独立卡片。
- 数据导入、导出与删除使用第 7.3 节规定的全屏分步任务界面；选择步骤以复选框决定内容范围，固定底栏汇总全部已选项目与来源，不使用可拖动关闭的底部面板。
- 文件保护与恢复方式在“设置与核对”步骤决定。导出默认加密整个所选范围，也可选择仅敏感内容加密、不加密或逐项自定义；保护方式与数据类别解耦，敏感明文应说明后果。
- 导入核对步骤注明内容是否已存在，并只提供实际支持的导入、替换或合并方式；不支持合并时就近说明原因。跳过内容通过返回选择步骤取消勾选完成。
- 永久删除继续要求独立确认；数据导入的替换或合并选择本身就是明确决策，不再额外叠加确认复选框。

### 5.5 标签、筛选和页签

- `SuiteStatusChip` 用于“已启用”“当前”“已验证”等短状态，不承载主要动作。
- `FilterChip` 用于可反复切换的筛选条件，不用作普通导航按钮。
- 同一插件内部有 3 个以上并列数据页时可使用 `ScrollableTabRow`；页签名称要短，内容区不再重复
  完整页面标题。
- 普通版本号是次要文本，不做成可点击 Chip，除非它真的打开版本选择。

### 5.6 按钮和菜单

- 当前对象只有一个明确下一步时使用满宽主按钮，例如“安装”“获取记录”。
- 两个并列动作可用等宽 `Button` + `OutlinedButton`，优先动作放在阅读顺序后侧。
- 同一上下文有多项次要动作时可使用 `MoreVert` 溢出菜单；只有插件设置一项时直接提供图标按钮。插件包与数据维护使用详情中的明确条目。
- 恢复、刷新、查看标准等轻量动作使用 `TextButton`。
- 禁用按钮旁必须已有原因文本，不能让用户猜为什么不可点。

### 5.7 状态与反馈

| 情况 | 组件／位置 | 规则 |
| --- | --- | --- |
| 初始加载 | 稳定页面外壳；确认长耗时后才使用 `LoadingState` | 默认直接呈现内容，不添加短暂占位文案；确需提示时使用简短动词，不展示实现阶段 |
| 内容为空 | `EmptyState` | 标题说明当前状态，正文给出下一步；动作放在空态旁 |
| 可恢复失败 | `ErrorState` | 说明失败对象和原因，能重试时提供按钮 |
| 可关闭提示 | `DismissibleNotice` | 仅用于确有持续价值的信息 |
| 短暂操作结果 | Snackbar | 主动操作必须反馈；可恢复失败可带“重试” |
| 对象级长任务 | 卡片内进度 | 进度与正在处理的对象保持空间归属 |
| 需要决策或确认 | `AlertDialog` | 标题说明决策，按钮使用明确动词 |
| 选择大量同类项 | `ModalBottomSheet` | 每行直接表达选中或执行结果 |

不要用 Toast 承载需要阅读或操作的结果，也不要用常驻横幅显示“已是最新版本”之类瞬时状态。

## 6. 现行交互模式

### 6.1 主页与工具排序

- 普通点按打开工具；长按不移动打开对象菜单，长按拖动提起卡片。
- “排列”进入明确的排列模式，显示手柄；卡片或手柄可直接拖动，点按打开移动菜单，“完成”或返回结束模式。
- 提起后保留实际占位，浮起项略微放大并增加阴影；占位随目标位置移动，周围卡片平滑让位。
- 靠近内容区上、下边缘时自动滚动；松手后浮起项移到落点，再保存顺序并提供一次撤销。
- 在内容区外松手、指针取消、返回或 Esc 取消本次拖动，恢复原顺序，不写入中间排列。
- 拖动期间固定结构顺序，后台任务继续运行；连接和授权状态仍更新原卡片，不把旧的“已连接”留到松手。
- 隐藏项保留在完整顺序模型中；撤销恢复包含隐藏项的原顺序。菜单和读屏提供上移、下移、移到开头、移到末尾。
- 排列模式支持键盘方向键、Home、End；减少动态效果设置缩短或取消动画，不改变最终顺序。

小部件菜单提供尺寸、“暂时隐藏”和“移除小部件”。隐藏保留实例，移除删除配置、布局偏好和摘要缓存，并要求确认；保留插件与业务数据。旧迁移不会重新创建已移除实例，这个选择也随应用设置备份与恢复。工具列表提供直接详情按钮；菜单可移入文件夹或工具收纳。收纳是可访问的二级列表，不停用插件，移出后恢复主列表。
排列模式不增加常驻启用开关、移除角标或多步撤销栈。

### 6.2 工具、仓库与插件详情

工具提供已安装插件、排序、整理与更新检查；仓库只展示未安装插件，并提供发布目录与本地包导入。已安装插件的更新与版本切换通过工具中的详情进入，不在仓库重复列出。
列表显示身份、版本与启用/更新状态，点击进入同一插件详情，决定打开、安装、启用或重启激活。
详情维护插件的启用、工具页显示、功能权限、版本、是否检查更新及插件包导出/移除；“插件数据”提供导出、导入和删除入口，仅处理此插件的内容。
首页小部件统一由主页的宿主入口管理；文件备份/恢复/清理使用宿主统一流程，设置中的数据管理负责跨应用与插件的操作，插件详情的入口限定当前插件范围。
权限子页不复刻身份卡，安装与发布元数据只出现在关于插件。

普通插件仅列出需要用户决定的权限，实际拒绝未授权调用；私有存储是运行基础，不单列为权限。
完全信任的系统插件明确说明可以直接使用应用拥有的权限，无法逐项限制；
其他普通插件使用其能力仍按调用方权限检查。
移除插件包与删除业务数据分别命名和确认，移除插件保留业务数据。

小部件管理使用完整子页，默认列出已添加实例，包括隐藏、插件停用或缺失的实例；每项提供配置、显示/隐藏和移除。添加页按插件列出预设，配置页使用宿主统一设置行与固定保存底栏，不再用按钮列表式大弹窗。设置页不重复提供该入口。

插件详情的“关于插件”提供安装与发布者、兼容性、来源和项目信息；版本与来源页只负责版本选择和当前安装来源提示。

### 6.3 正式发布与更新

只展示正式最新及历史发布；版本与来源页说明当前安装与正式目录的匹配结果。
版本选择仍检查兼容性和降级条件。更新数量、提示与“全部更新”只计算已安装且允许检查更新的插件。
手动刷新有结果反馈，自动检查无更新或失败保持静默。“稍后”“本次不再提示”“全部更新”保留不同后果。
本地 Debug 应用没有远端应用更新；正式应用与插件的自动检查分别设置。插件目录不设置 Debug 渠道。

## 7. 宿主页与任务模式

### 7.1 主页和工具

主页使用“常用，一眼可见”组织小部件，头部操作依次为新建文件夹图标、排列与“小部件”管理；两个文字入口相邻，存在可用更新时显示更新入口。
主页只显示小部件。可建立文件夹归类多个相同或相近功能的小部件；文件夹封面可调整尺寸，打开后显示真正的小部件，保留绑定、尺寸、点按和配置能力。解散只把成员放回主页，不删除实例或数据。

插件贡献的是预设，同一插件可添加多张独立配置的实例。主页的“小部件”打开统一管理页，卡片长按的“配置小部件”进入独立编辑步骤；插件自身不铺设这个公共入口；保存前使用草稿，取消不改已有实例。账号、卡池与历史范围固定在当前卡片，插件内浏览不改变首页。插件停用、账号删除或权限不可用时保留配置并明确提示，不静默改用另一个账号。

小部件管理按插件分组，紧凑显示绑定摘要、布局和显隐开关，点按名称进入配置，移除保留独立确认。“布局”选择同时决定预设与受支持尺寸，不分成两项互相约束的下拉。4×2 趋势卡片左侧显示数值、账号及范围，右侧约一半宽度留给历史图与日期；2×2 采用上下布局。点按卡片进入所绑定的档案、账号或卡池，该定位仅作用于当前页面会话；旧入口不得在普通打开或重新创建页面时重复播放。

Phigros 默认使用四位 RKS、变化量与真实历史折线，支持 7/30/90 天和全部；空历史、单点、平稳与下降如实表达，亦可选择纯数值预设。抽卡提供固定账号的单池进度、最多四池的宽幅概览，以及按游戏汇总的账号数、记录数和最近记录时间。不从当前值虚构历史或展示进度。

旧主页迁移保留顺序、尺寸、隐藏状态，并仅在首次迁移固定已有账号选择；配置读取失败保持未配置状态。实例、已完成迁移标记与文件夹进入应用设置备份，恢复时按所属插件保留边界；明确保存的空布局不会被旧默认卡片填充。
系统状态部件保持稳定位置，连接重新确认后才显示已连接。

低频搜索按需展开：工具、管理、仓库、数据来源清单和服务列表在分段操作区提供搜索按钮，关闭时清除关键词并收起软键盘。页面返回保留仍生效的关键词；不能隐藏已经生效的条件。成绩、曲库和原始记录的搜索继续直接可用；数据任务中的搜索按需展开，已生效的关键词与来源条件保持可见。
工具页默认显示可用工具及排列入口。工具卡使用图标底座、名称和描述，
常态显示进入指示，排列时显示手柄。工具收纳入口说明收纳数量，可进入二级列表整理或移回；收纳不会停用插件。
空搜索与没有可用工具分别提供清除搜索、发现插件等操作。

### 7.2 设置与关于

设置按外观、应用更新、插件更新、管理和关于组织，统一使用图标、辅助说明和尾部状态。上次检查时间属于检查更新行的辅助信息。旧数据迁移说明仅从实际识别到旧备份或旧格式的上下文进入，不占常驻设置入口。关于使用标准返回顶栏，
显示版本、SDK、构建、项目、发布中心和许可；版本行支持长按复制完整版本串。发布中心与项目、许可采用相同设置行和尾部导航箭头，不单独引入左侧图标。

### 7.3 数据管理与选择

数据管理按应用/插件来源显示真实本地内容，从设置进入。浏览某个来源不改变导入、导出和删除的操作范围；三项操作统一位于同一动作区，并在各自的选择步骤确定范围。来源详情不重复增加删除入口。
导出、导入与删除在同一行等宽操作区，危险动作使用明确文字和语义色。数据备份使用 `ATS-data-<本地日期时间>.atsbackup`，仅包含一个插件时保留插件标识；UIGF 与成绩图片保留内容类型和本地日期时间，不附加软件版本。插件包导出只保留插件标识与版本，不带日期时间。Debug 应用在所有导出文件扩展名前添加 `-debug` 标识，包括备份、插件包、UIGF、图片与其他插件文件；这是导出来源标识，不改变包内版本或内容。归档内部格式与版本保持不变。
数据包导出、导入和数据删除共用“选择内容 → 设置与核对 → 执行结果”的流程；
执行结果进入任务与结果，不把一次页面动画当成业务完成。

选择步骤只决定对象：支持关键词、来源筛选、只看已选、分组选择、全选当前和取消当前选择。
批量操作仅作用于当前筛选结果，其他范围的选择保留；依赖自动联动并由底层再次校验。
固定底栏汇总全部已选内容与来源，宽屏可增加选择摘要。删除默认不选内容，提供只选当前缓存。

设置与核对步骤承载操作相关决定：

- 导出默认加密整个所选范围，可选择仅敏感内容加密、不加密或逐项自定义；仅在需要时输入密码，保留当前安装的插件包以便恢复本地版本。
- 导入先识别文件内容，再按照真实支持的方式选择合并、替换或导入；核对替换范围，不能合并的项目说明原因。
- 删除列出最终影响，要求明确确认永久删除；返回修改范围后清除原删除确认。

标题、步骤和底栏固定，中间列表独立滚动。手机全屏，宽屏内容不超过 720 dp，正确处理系统栏与软键盘。
返回上一步保留范围、筛选和滚动；有选择修改或密码时，退出需要确认放弃。
系统文件选择取消或失败保留任务上下文，失败不会假装成功，也不清空可重试的选择。
未知备份版本拒绝导入；旧迁移包仅恢复可识别的应用状态，不恢复旧可执行插件代码或继承系统授权。

### 7.4 任务与结果

数据包导入、导出、删除、插件安装，以及插件内用户主动发起的同步、导入导出和图片保存等操作，创建实际操作记录，展示真实状态、说明及可获得的逐项结果。
处理中、成功、部分完成、失败和取消分别表达；只有底层操作完成才标为完成。失败提供返回对应数据或插件来源的入口。
插件通过所属 UI 会话上报固定动作标签与安全结果，不上传凭据、链接或业务载荷。工具页面保留期间可继续更新任务；页面被释放后，尚未结束的操作标为取消。返回工具后由用户决定是否再次执行，不能把返回入口描述成已经重试。
任务列表的保留范围是本次应用使用，不承诺跨进程的永久日志，也不虚构跨插件统一进度百分比。

## 8. 插件页面指导

### 8.1 接入方式

- Runtime v2 页面统一从 `ui/*.json` 声明式入口启动；简单页面使用 `column` 根节点，由宿主直接渲染共享 Compose 组件；
- 复杂页面使用 `webview` 根节点选择 WebView renderer，并只消费宿主注入的 `--ats-*` CSS token，不复制色板或类型层级；正文、标题、标签和按钮分别使用对应的 `--ats-type-*` 字号、行高与字重，不继承浏览器默认值；
- 宿主私有 Compose 页面与 trusted-provider 共享 UI 继续使用公开设计 token；普通插件只使用 format v3 Host/WebView 声明入口。
- 页面优先复用 SDK 的 `SuiteCard`、`SectionHeader`、`EmptyState`、`LoadingState`、
  `ErrorState`、`DismissibleNotice`、`SuiteStatusChip` 和设置行组件。
- 不复制颜色、间距、圆角或浅色专用 View 工具；`UiKit.java` 已废弃，不用于新页面。
- 插件详情顶栏由宿主提供，插件根内容不要再添加返回按钮或应用级标题栏。
- Host renderer 使用契约提供的共享 Material 图标；WebView 当前只注入主题 CSS，没有共享图标资源端点，刷新等操作使用明确文字按钮，不用“辅”“✓”“♥”“↻”等字符模拟功能图标。

数据插件保留明确账号上下文和就地刷新。Phigros 的业务标签均分可用宽度；抽卡根页直接切换游戏，明细从统计范围继续进入。
内容数据就绪后统一出现，刷新与云同步期间可继续浏览已有本地内容；写入和重复提交仍受忙碌状态限制。
WebView 弹窗按当前可用区域限制高度并在内部滚动，不依赖 Android WebView 可能错误计算的动态视口单位；验收必须检查内容实际位于弹窗可视区域，不能只验证 DOM 存在。
搜索和筛选作用于完整数据，换页只改变可见项。加载结束恢复按钮原有可用性，不启用缺少必要数据的动作。

Phigros 使用“总览／成绩／时间线／定数表”。总览优先展示存档官方 RKS、真实近期变化、课题/成绩/Data 指标、玩家信息和难度统计；
真实本地历史趋势支持 7/30/90 天和全部，默认 30 天，空历史、单点和下降如实表达。时间范围只筛选真实样本；绘图使用所选样本的首末时间和固定绘图区边距，保留实际时间间距，单点居中，不补造两端数据。账号名称排列在 RKS 右侧、计算规则下方；简介、完整多单位 Data 余额、存档时间与图片入口直接展示，避免折叠入口推低趋势图。
点击趋势节点进入该次变化；RKS 与成绩时间线直接浏览全部历史并分页，分别展示计分原因和实际成绩变化。
难度统计按 EZ/HD/IN/AT 独立展示 Clear、FC、AP，点击数量进入相应条件；不相加推算总成绩数。

### 8.2 内容层级

推荐顺序是：

1. 必要的账号／数据源选择；
2. 当前关键结果或状态摘要；
3. 页签或筛选；
4. 详情卡片；
5. 与当前业务有关的详情动作；文件与批量清理在专门管理页。

同一页不要同时用大标题、强调卡、彩色数值和多个主按钮争夺焦点。统计卡中的颜色要有标签，
例如“UP”“歪”“推分 ACC”，不能只用绿／红区分。

### 8.3 插件自有颜色

插件可为稀有度、难度或品牌维护领域色。使用 `SuiteTheming.isDark` 选择深浅档；如果该颜色表达
成功、警告、危险或信息，应直接改用 `SuiteSemantic.current`。领域色与背景的对比度不足时，
优先增加文字、形状或图标，而不是继续提高饱和度。

### 8.4 敏感信息和风险文案

- 不显示或记录 SessionToken、AuthKey、Cookie 等完整凭据。
- 说明实际数据范围和后果，例如“仅在本机加密保存”“不写入数据库”“导入只合并新记录”。
- 用户界面使用“应用”“插件”“版本”等用户词汇；`宿主`、`versionCode`、`同一进程`、
  `索引签名` 等实现词只在确实帮助诊断的关于页或开发文档中出现。

## 9. 无障碍与可用性

- 所有图标按钮提供动作含义；纯装饰图标的 `contentDescription` 设为 `null`。
- 整行点击与行内 Switch／菜单必须各自可操作，不留下内边距死区。
- 最小触摸目标遵循 Material 组件默认值，紧凑视觉不等于缩小命中区域。
- 拖拽必须同时提供读屏自定义动作；颜色信息必须有文字或图标冗余。
- 文本允许系统字号放大，卡片标题和尾部状态应能换行或省略，不依赖固定像素宽度。
- 浅色、深色、动态取色、竖屏、横屏、手机、宽屏和 TalkBack 都属于发布前检查范围。

## 10. 文案规则

| 不推荐 | 推荐 | 原因 |
| --- | --- | --- |
| 要求宿主 `versionCode ≥ 18` | 需要应用 1.5.0 或更高版本 | 给用户可理解的版本与解决方向 |
| 3 个内置 · 1 个外部 | 4 个工具已就绪 | 不暴露实现分类 |
| 仓库索引签名验证成功 | 已验证发布 | 保留结果，不展示机制 |
| 操作失败 | 仓库刷新失败：网络连接超时 | 说明对象和原因 |
| 确定 | 删除插件／全部更新／重新安装 | 按钮表达实际后果 |

文案优先回答“现在是什么状态”“我能做什么”“操作会影响什么”。安全风险和数据范围不能为了
简短而省略，但应写成用户后果，不写架构自述。

## 11. 不再采用的旧方案

以下旧方案不再作为后续实现目标：

- 把管理和仓库包进同一个一级页的子页签，增加切换层级却没有减少操作；两者保持直接入口。
- 工具页内常驻启用开关、移除角标、尺寸缩略图面板和多步撤销栈；排列模式只处理顺序。
- 抽卡横向卡池轮播承担总览选择、Phigros 将全部成绩字段永久展开、只有固定难度按钮而无定数与评级组合筛选。
- 选择数据时同时决定加密/明文；保护与恢复方式进入下一步核对。
- 在页面初次读取时临时展示摘要、零值或空态，或用固定等待时间充当真实性能依据。
- 用样例曲线、跨用户排名、百分比或任务动画承诺尚未取得的数据和能力。

## 12. 评审清单

新增或修改宿主／插件 UI 时至少核对：

- [ ] 页面职责符合四个一级入口和二级页面边界；
- [ ] 使用 SDK token 与共享组件，没有新增近似颜色、间距或圆角；
- [ ] 浅色、深色和动态取色下前景／容器配对正确；
- [ ] 页面只有一个主要视觉焦点和一个明确主动作；
- [ ] 空、加载、失败、禁用、处理中和完成状态均有设计；
- [ ] 新增加载中间态有代表性实测支持，确认需要持续等待；短时读取没有临时文案、摘要、骨架或误导性空态；
- [ ] 已检查快速完成、提示阈值附近完成、慢加载和失败的实际过渡，必要时逐帧检查录屏；不以换词、渐入或延迟最终内容掩盖闪烁；
- [ ] 主动操作有反馈，后台无结果不会产生噪音；
- [ ] 高风险动作写明后果并在需要时确认；
- [ ] 图标、Switch、菜单、拖拽和自定义动作可被读屏使用；
- [ ] 手机与 `>= 840 dp` 宽屏布局均正确；一级内容不超过 `720 dp`，插件详情使用 `720 dp` 居中单栏；
- [ ] 文案使用用户语言，不泄露凭据，不用实现术语替代说明；
- [ ] HTML 样例、本规范和实际 Compose 实现没有互相矛盾。


### 文件夹、紧凑尺寸与常用场景

主页文件夹的成员是小部件实例，工具文件夹的成员是插件，两者保持独立。成员同一范围只属于一个文件夹，排序、收纳和文件夹变更一起保存在应用设置中；数据恢复的合并保留本机成员位置并补充未归类的新成员。文件夹允许为空；新建与编辑只填写名称，不选择成员。成员通过长按拖入、在文件夹内拖至移回区域或可访问的移动菜单整理。文件夹不嵌套，解散不删除成员。紧凑状态卡优先显示实际状态，UID 等技术信息不占用主要数值位置。

主页使用 1×1 占用格子，宽高独立，不按一行中最高部件封闭整行。部件保存列与行坐标，可以放进空格或移动到空白区域；碰撞时仅将冲突部件移至空位。排列时显示格线，移动、恢复和调整尺寸后不能产生重叠。网格单位支持 1–4 的宽和高，具体可选组合仍由预设声明。文件夹支持不同尺寸：1×1 只显示名称与数量，较大尺寸展示真实缩小的小部件内容；文件夹内仍使用部件自身的尺寸。信息较少的系统状态支持 1×1、1×2、2×1；紧凑状态卡的数字须带含义，例如“1 个已启用”，不能只显示“1”。紧凑模式减少说明，保持正常尺寸原有信息密度，不因特殊字号重排普通布局。设计和验收以常用手机尺寸、正常字号、实际内容为主，特殊字体与窄屏只作补充。

抽卡多池概览分别固定原神与星铁账号，卡池标识带游戏，最多四池，可混合两个游戏。旧单游戏绑定保持兼容；工具内的浏览账号不改变绑定。

### 数据选择与合并

数据选择首先按来源收起分组；搜索、来源过滤和批量选择按需使用，不铺满顶端。设置与核对页在每个已选内容附近显示处理方式，默认采用实际支持的合并，替换必须明确选择。内容依赖、密码保护、失败后选择保留和事务回滚继续有效。

合并由接收方声明的数据规则决定，旧备份的替换声明不限制新接收方的合并能力。账号、记录和历史按稳定标识去重；已有设置和凭据保留，补充缺失项；Phigros 保留较新的当前存档，历史与定数修订分别合并。无法可靠合并的整体缓存保留替换选项，说明原因。

抽卡链接在独立的敏感 Dataset 中加密缓存，按游戏与账号隔离，进入获取页按需读取，不自动联网；明确失效或手动清除后删除。日志检索查找系统保留的全部匹配范围，继续受已授权关键词和输出边界约束。

记录分布按票券类型着色，每种票券内按卡池分段，支持票券／卡池组合筛选。图例、筛选、堆叠条和饼图采用固定顺序：相遇之缘／星轨通票在前，纠缠之缘／星轨专票在后；千星奇域独立分组，使用常驻颂愿、活动颂愿。月份与版本维度均按抽数展示，先进入同一范围的简要分析，更多菜单再打开明细，返回保留筛选与浏览位置。星铁版本日期日历转换到 UTC+8 进行匹配，未覆盖的日期保留未知。不提供按 UP 获取次数聚合的维度，不推测资料不完整的版本上下半与具体 UP 卡池归属；所有分析不修改原始记录。

分析页的更多菜单在点按外部、返回或 Esc 时关闭，保留当前分析和滚动位置；关闭菜单后再返回上一级。

工具卡片的详情按钮独立处理触摸，父卡片不能在其点击后再次打开工具。抽卡账号行的文本区域可伸展，尾部箭头采用固定图标尺寸；账号与获取记录按钮共享上下边界，进度条不能在空闲时增加间隔。Phigros 的全部成绩与 B30 使用相同成绩行与列表间距，分组标题仍表达 P3 / B27 边界。

# ATS AI 插件开发计划

前置条件：Runtime v2 的清单、Capability、Dataset、后台任务和包签名契约冻结

## 1. 边界

AI 能力分成两个互不替代的角色：

1. Developer Agent：帮助创建、修改、测试和解释插件项目，只在开发工作区与草稿运行时中工作。
2. AI Provider：由已安装插件通过显式 Capability 调用的模型服务，遵守普通 Provider 的版本、授权、配额和审计规则。

Developer Agent 不能因为“由 ATS 提供”就越过插件签名、Capability 同意或人工发布确认；AI Provider 也不能获得修改插件源码、安装新插件或发布制品的隐式权限。

## 2. 共同契约来源

下列产物必须从同一份 Runtime v2 契约生成，避免文档、Agent 和运行时各维护一套能力描述：

- TypeScript SDK 类型和方法说明；
- Agent 可检索的 Capability 目录；
- 清单与 Dataset schema；
- Mock Capability、错误样例和权限情景；
- 契约测试、兼容性检查与文档片段。

Agent 的 `inspect`／`catalog` 输出只能描述当前契约实际提供的能力，不得根据自然语言临时发明宿主 API。

## 3. 确定性开发流水线

```text
用户目标
  -> Agent 生成或修改源码、清单与测试
  -> schema / lint / unit / contract tests
  -> Draft Runtime + Mock Capabilities
  -> 人工查看差异、权限、数据和后台行为
  -> 可复现构建与签名
  -> 安装或交给发布工作流
```

模型输出本身不是可安装制品。每次构建必须记录源码快照、依赖锁、工具链版本、测试结果和制品摘要；相同输入应能重建相同逻辑内容。非确定性的模型调用只发生在生成阶段，不进入签名构建步骤。

## 4. Draft Runtime

草稿运行时提供：

- 独立的草稿插件 ID、存储命名空间和可清除数据；
- Capability Mock 与情景切换，如成功、拒绝、超时、离线和 Provider 崩溃；
- 虚拟时钟、后台任务手动触发、重试和并发检查；
- 网络、文件、通知和敏感数据访问的可见日志，但自动遮蔽凭据内容；
- 与正式 Runtime 相同的清单和 RPC 校验，不提供“开发模式特权 API”。

草稿插件默认不能写入正式插件数据。需要迁移 fixture 时使用显式导入副本，不直接挂载生产命名空间。

## 5. 人工批准门槛

安装或发布前至少展示：

- 源码差异和生成说明；
- 新增或扩大后的 Capability；
- Dataset 读写、删除与迁移变化；
- 后台任务触发、最大运行时间、网络和通知行为；
- 测试结果、已知限制、依赖与制品摘要。

删除数据、发送外部请求、改变后台计划或扩大权限属于高影响变化，不能通过“一键接受所有 AI 修改”静默批准。

## 6. 生命周期与可逆影响

Agent 生成的插件必须声明可观察的外部影响及撤销方式：

- 安装／启用／停用／卸载；
- Dataset 创建、升级、导入和删除；
- 定时任务注册与取消；
- 通知渠道、文件授权和 Provider 绑定；
- 失败后的回滚或人工恢复步骤。

首版只自动执行有明确事务或补偿操作的变更。无法撤销的外部操作必须在预览中单列，并在执行点再次确认。

## 7. 分阶段交付

### A1：只读助手

- 读取本地契约与示例；
- 解释构建、校验和错误；
- 生成建议差异但不自动应用、不安装。

### A2：草稿生成

- 创建最小 Web Tool；
- 生成源码、清单、测试和 fixture；
- 在 Draft Runtime 中运行 Mock Capability 契约测试。

### A3：受控修改与本地安装

- 逐差异批准；
- 记录来源证明和可复现构建信息；
- 只安装到 Debug／草稿槽位。

### A4：接入发布草稿

- 把批准后的源码快照、构建记录和制品交给 ATS 发布平台的私有草稿区；
- 发布、签名和可见性仍由平台工作流独立确认。

## 8. 非目标

- 不让运行中的普通插件自行修改或替换其代码。
- 不允许模型直接调用裸 Shell、任意文件路径、签名密钥或发布凭据。
- 不用 AI 绕过缺失的 Runtime v2 Capability；缺能力时应提出契约变更建议。
- 本计划不实现模型托管市场、社区推荐或 iOS 开发链。

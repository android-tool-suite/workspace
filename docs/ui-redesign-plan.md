# Android Tool Suite UI 设计模式规范与实现指南

本文定义 Android Tool Suite 宿主应用与插件共同遵循的 UI 设计语言、页面模式和交互规则。
文件名沿用 `ui-redesign-plan.md` 以保留既有链接，但它不再是一份待实施的重设计计划。

配套样例：[ui-redesign-preview.html](ui-redesign-preview.html)。HTML 用于查看浅色／深色配色、
核心组件、五个一级页面、插件详情和状态反馈；它是可离线打开的独立本地 HTML，内嵌图标并保留许可，
不依赖 Codex 运行时或在线 CDN。页面中的数据与外部操作均为演示，实际组件与业务状态以代码为准。

## 1. 适用范围与事实来源

本规范适用于：

- 宿主的主页、工具、管理、仓库、设置、关于和插件详情容器；
- `plugin-sdk` 提供的 Compose 设计系统；
- 无障碍授权、Phigros Data Studio、抽卡分析及后续外部插件；
- 空态、加载态、错误态、拖拽态、弹窗、底部面板和 Snackbar。

发生差异时按以下顺序判断：

1. `app/plugin-sdk/.../SuiteDesignSystem.kt`、`SuiteTokens.kt`、`SuiteSettings.kt`、
   `SuiteStates.kt` 中的公开 token 和组件；
2. `app/app/.../HostAppUi.kt` 中已经交付的宿主模式；
3. 本文的说明和 HTML 样例。

规范描述的是当前已经采用的设计基线，不把未实施设想写成既定行为。后续若修改基线，应同时
更新 SDK、宿主、受影响插件、本文和预览页。

## 2. 设计原则

### 2.1 按用户意图划分页面

同一动作应有清晰主归属，允许在最贴近上下文的位置提供快捷入口，但不要让多个页面承担完全
相同的主职责。

| 用户意图 | 主归属 | 可接受的快捷入口 |
| --- | --- | --- |
| 查看状态、进入常用能力 | 主页 | 小部件点按进入插件 |
| 浏览和打开全部工具 | 工具 | 长按菜单可隐藏、停用或前往管理 |
| 控制插件是否启用、在哪里显示、是否检查更新 | 管理 | 工具页长按可前往管理 |
| 安装、更新、切换版本、导入插件包 | 仓库 | 管理展开区可导出或删除已安装插件 |
| 主题、配色、自动更新、迁移、调试渠道 | 设置 | 无 |
| 查看构建与许可信息 | 关于 | 设置中的“关于”入口 |

### 2.2 先让状态可扫，再让细节可展开

- 列表首屏优先呈现名称、关键状态和最常用动作。
- 管理列表显示摘要，点按打开该插件的详情面板；摘要覆盖启用、显示位置和更新检查等重要状态。
- 版本、来源、兼容性和进度放在对应对象附近，不使用全局大横幅代替局部状态。
- 低频操作进入展开区、溢出菜单或底部面板；不要把每项能力都平铺成按钮墙。

### 2.3 一屏只突出一个主动作

- `Button` 表示当前卡片或步骤的主要下一步。
- `OutlinedButton` 表示并列但次要的动作。
- `TextButton` 表示轻量导航、恢复、刷新或关闭。
- 删除、覆盖、降级等高风险动作不得仅靠颜色区分，必须使用明确动词，并在不可逆时确认。

### 2.4 安静地处理后台工作，明确反馈主动操作

- 启动时自动检查：无更新或失败均保持静默；有更新才提示。
- 更新提醒、数量和“全部更新”只包含已安装插件；仓库存在但未安装的项目留在“可安装”列表。
- 启用需要冷启动激活的系统插件时，显示不会自动消失、不能点外部或返回键关闭的确认弹窗，提供“立即重启”“稍后重启”。选择稍后后，管理卡片保留“重启以激活”入口；立即重启应重启当前应用进程。
- 用户主动检查：开始、成功和失败都要有 Snackbar 或就地反馈。
- 下载、导入、安装进度放在对应应用或插件卡片内。
- 可恢复的列表刷新错误使用 `ErrorState` 并提供“重试”。

### 数据加载与页面保留

- 已有主页摘要时直接显示，后台刷新不清空卡片；主页不可见时仅标记数据变化，返回后合并刷新；首次无数据时使用稳定标题与数值占位，不闪过旋转动画。
- 摘要按插件包版本和数据代际隔离，数据写入／恢复后失效；撤销权限时立即清除相关展示缓存。
- 系统连接和授权状态不从磁盘恢复为已确认状态，进入前台重新确认。
- 当前 Activity 保留最近两个插件页面，返回时恢复页面内容、页签与滚动；第三个页面进入后释放最久未使用页面。停用、更新或 Activity 销毁会释放对应页面。
- Phigros 先展示本地摘要，完整成绩随后补全。刷新失败保留已显示内容并就地提示。

### 2.5 共享外壳，保留领域表达

宿主和插件共享布局密度、圆角、主题、语义色、状态组件和动作层级。游戏稀有度、谱面难度等
领域色可以由插件维护，但必须同时提供浅色／深色方案，并用文字或图标补充语义，不能只靠颜色。

## 3. 信息架构与导航

### 3.1 五个一级入口

手机使用底部导航，宽屏使用侧边导航栏，顺序固定为：

1. 主页
2. 工具
3. 管理
4. 仓库
5. 设置

五页可左右滑动切换，底栏／侧栏选中态与页面位置同步。仓库有可用更新时显示数量角标。

一级页不重复放顶栏标题。内容本身用大标题、说明或分段标题建立层级，避免底栏标签、顶栏标题、
内容标题连续重复同一个词。

### 3.2 二级页面

插件详情和关于是压在一级分区之上的独立页面，统一使用 `SuiteTopBar`：

- 左侧返回箭头；
- 中间为当前对象名称；
- 右侧只放与本页对象有关的操作；
- 返回后恢复进入详情前的一级分区和滚动上下文。

不要在插件内容内部再绘制一套应用级顶栏。插件可在内容区使用页签、筛选器和分段标题。

### 3.3 响应式边界

- 一级内容最大宽度为 `720 dp`，宽屏时居中。
- 可用宽度达到 `840 dp` 时，底部导航切换为侧边导航栏。
- 所有分支都必须处理状态栏、导航栏和手势区域 inset。
- 响应式变化只重排导航和可用宽度，不改变功能归属或文案含义。

## 4. 视觉 token

代码中必须使用 `SuiteSpacing`、`SuiteShapes`、`MaterialTheme.colorScheme`、
`SuiteSemantic.current` 和 `MaterialTheme.typography`。下列数值用于设计稿、评审和 HTML 对齐，
业务代码不要复制一套常量。

### 4.1 间距

| Token | 数值 | 常见用途 |
| --- | ---: | --- |
| `xs` | 4 dp | 同一信息组内的紧密间隔 |
| `sm` | 8 dp | 标签、按钮内容、状态信息 |
| `md` | 12 dp | 列表间隔、图标与文字、设置行垂直内边距 |
| `lg` | 16 dp | 内容块间隔、展开区内边距 |
| `xl` | 20 dp | 页面水平边距、卡片主要内边距 |
| `xxl` | 24 dp | 页面垂直边距、较大分组间隔 |
| `xxxl` | 32 dp | 独立大区块间隔 |

默认一级页使用 `20 dp` 水平边距、`24 dp` 垂直边距；卡片列表间隔优先使用 `12 dp`，
跨分段间隔使用 `14–16 dp`。

### 4.2 圆角

| Token | 数值 | 用途 |
| --- | ---: | --- |
| `SuiteShapes.Card` | 24 dp | 主卡片、空态、错误态、重要面板 |
| `SuiteShapes.Inner` | 16 dp | 卡片内区域、图标底座、进度与领域信息块 |
| `SuiteShapes.Chip` | 12 dp | 状态标签、密集图标底座、短选择器 |
| `SuiteShapes.Dialog` | 28 dp | 对话框和高层浮层 |

胶囊按钮、Switch 和进度条可使用完整圆角。不要在业务页面继续引入 8、18、20、22 dp 等
近似但不同的卡片圆角。

### 4.3 品牌色与主题

默认使用应用自带 teal 色板；Android 12 及以上可由用户选择跟随壁纸。主题可跟随系统，也可
固定浅色或深色。插件必须通过 `composePluginView`／`SuiteTheme` 读取宿主选择，不得自行读取
系统主题后覆盖宿主设置。

主要色板：

| 角色 | 浅色 | 深色 |
| --- | --- | --- |
| `primary` | `#006B5F` | `#82D5C6` |
| `primaryContainer` | `#C3E4DC` | `#005047` |
| `secondaryContainer` | `#D5E7E2` | `#334B47` |
| `background` / `surface` | `#F7FAF8` | `#0E1513` |
| `surfaceContainerLow` | `#F0F5F2` | `#151C1A` |
| `surfaceContainer` | `#EAF0ED` | `#1A2220` |
| `surfaceContainerHigh` | `#E3EAE6` | `#252D2A` |
| `surfaceContainerHighest` | `#DCE5E1` | `#303936` |
| `surfaceVariant` | `#DAE5E1` | `#3F4946` |
| `outline` | `#6F7976` | `#89938F` |
| `outlineVariant` | `#BFC9C5` | `#3F4946` |
| `error` | `#BA1A1A` | `#FFB4AB` |

成功、警告、危险和信息必须使用 `SuiteSemantic.current` 的成对前景／容器色：

- 实心语义色使用 `success` + `onSuccess` 等组合；
- 浅底信息块使用 `successContainer` + `onSuccessContainer` 等组合；
- 不要把白字直接放在浅色 warning／success 容器上；
- 已废弃的 `SuiteColors` 和硬编码浅色值不得用于新代码。

### 4.4 字体层级

| 样式 | 使用场景 |
| --- | --- |
| `headlineLarge` | 主页“工具台”等单一页面主标题；一屏通常只出现一次 |
| `headlineSmall` | 关键结果、账号名、核心数值 |
| `titleLarge` | 分段标题、卡片主区标题、底部面板标题 |
| `titleMedium` | 列表卡标题、设置入口名称 |
| `bodyLarge` | 页面主说明 |
| `bodyMedium` | 卡片说明、常规正文 |
| `bodySmall` | 版本、时间、数量、兼容性等元数据 |
| `labelLarge` / `labelMedium` | 分类标记、按钮、短状态 |

使用主题字重，不在每个插件中重复指定相近的字号和粗细。大数值可加粗，但同一卡片内只保留一个
最强视觉焦点。

## 5. 页面骨架与组件模式

### 5.1 页面和分段

- 一级长页面优先使用 `LazyColumn`，保留滚动位置。
- 页面首部只在确实需要身份或摘要时使用大标题；工具、管理、仓库、设置可直接进入说明或分段。
- 分段使用 `SectionHeader(title, subtitle, action)`。副标题负责数量或上下文，右侧动作只放
  “刷新”“全部更新”“添加”等和整个分段有关的操作。
- 不用卡片包住整个页面，也不用卡片包住每个设置分组。

### 5.2 卡片

普通内容优先使用 `SuiteCard`：

- 默认 `surfaceContainerLow`、无阴影、`24 dp` 圆角；
- 内部水平 `20 dp`、垂直 `18 dp`，内容间隔 `8 dp`；
- 标题后接说明、状态或动作，不塞入与对象无关的全局信息；
- 强调摘要可使用 `primaryContainer`，但一屏不要出现多张同等强调卡。

可展开管理卡使用同样的圆角和底色；展开时用 `2 dp primary` 描边建立归属。整行可点按展开，
启用 Switch 保持独立点击目标，多张卡可以同时展开。

### 5.3 图标底座

工具和插件列表使用圆角方形底座统一视觉重量：

- 普通工具卡：`48 dp` 底座、`24 dp` 图标、`Inner` 圆角；
- 密集管理／仓库行：`38 dp` 底座、`20 dp` 图标、`Chip` 圆角；
- 底色 `secondaryContainer`，图标 `onSecondaryContainer`；
- 图标若是卡片上唯一的类型信息，要提供可理解的 `contentDescription`。

### 5.4 设置行

设置页使用 `SuiteSettingsGroup`、`SuiteSettingsRow`、`SuiteSettingsSwitchRow`，不使用卡片堆叠：

- 整行最小触摸区域按 Material 组件保证，标题使用 `bodyLarge`；
- 补充说明使用 `bodySmall`，当前值放右侧；
- 有下拉选择时同时显示当前值和向下箭头；
- “立即检查”等需要反馈当前状态的动作可用 `emphasized = true`；备份与迁移入口保持普通设置行配色；
- 装饰性图标不要给每行都加，只有“关于”等需要对象身份的入口使用图标底座。
- 数据包项目较多时使用“owner 分组 → Dataset 行”的两级展开，不把所有插件摊成一列；分组标题和展开后的 Dataset 行必须位于同一个描边圆角容器中，Dataset 行使用 `surfaceContainerLow` 与 `outlineVariant` 分隔线，不拆成多张独立卡片。
- 导出和导入都使用接近全高的 `ModalBottomSheet`。导出顶部汇总已选、明文和加密数量；导入说明来源，并在底部汇总将导入的数量。
- 导出 Dataset 行始终同时显示“不导出／明文／加密”三个 `FilterChip`，不能用额外复选框或会变字的按钮隐藏第三种状态。
- 保护方式与数据类别解耦：普通设置或业务数据也可进入密码区，Secret／敏感数据也可由用户明确改为明文。敏感项目默认加密；改为明文后，在主操作附近说明未加密文件可被直接读取，不增加无意义的确认行。
- 导入 Dataset 行必须注明“当前没有数据”或“已有数据”。前者显示“跳过／导入”；后者显示“跳过／替换／合并”。插件不支持的方式保持可见但禁用，并紧邻说明原因。
- 永久删除继续要求独立确认；数据导入的替换或合并选择本身就是明确决策，不再额外叠加确认复选框。

### 5.5 标签、筛选和页签

- `SuiteStatusChip` 用于“已启用”“当前”“已验证”等短状态，不承载主要动作。
- `FilterChip` 用于可反复切换的筛选条件，不用作普通导航按钮。
- 同一插件内部有 3 个以上并列数据页时可使用 `ScrollableTabRow`；页签名称要短，内容区不再重复
  完整页面标题。
- 普通版本号是次要文本，不做成可点击 Chip，除非它真的打开版本选择。

### 5.6 按钮和菜单

- 当前对象只有一个明确下一步时使用满宽主按钮，例如“安装”“获取记录”。
- 两个并列动作可用等宽 `Button` + `OutlinedButton`，优先动作放在阅读顺序后侧。
- 低频动作使用 `MoreVert` 溢出菜单，例如选择版本、导出插件包、删除。
- 恢复、刷新、查看标准等轻量动作使用 `TextButton`。
- 禁用按钮旁必须已有原因文本，不能让用户猜为什么不可点。

### 5.7 状态与反馈

| 情况 | 组件／位置 | 规则 |
| --- | --- | --- |
| 初始加载 | `LoadingState` | 简短动词，不展示实现阶段 |
| 内容为空 | `EmptyState` | 标题说明当前状态，正文给出下一步；动作放在空态旁 |
| 可恢复失败 | `ErrorState` | 说明失败对象和原因，能重试时提供按钮 |
| 可关闭提示 | `DismissibleNotice` | 仅用于确有持续价值的信息 |
| 短暂操作结果 | Snackbar | 主动操作必须反馈；可恢复失败可带“重试” |
| 对象级长任务 | 卡片内进度 | 进度与正在处理的对象保持空间归属 |
| 需要决策或确认 | `AlertDialog` | 标题说明决策，按钮使用明确动词 |
| 选择大量同类项 | `ModalBottomSheet` | 每行直接表达选中或执行结果 |

不要用 Toast 承载需要阅读或操作的结果，也不要用常驻横幅显示“已是最新版本”之类瞬时状态。

## 6. 现行交互模式

### 6.1 主页小部件

- 点按小部件：进入所属插件。
- 主页小部件不显示重复的“已就绪”标签；只有状态异常时显示“需处理”。全信任 Provider 使用 `primaryContainer` 强调背景，普通插件继续使用原有的 `surfaceContainerLow` 浅色背景。
- 长按后不移动：打开当前菜单，调整尺寸或从主页移除。
- 长按并拖动：显示落点虚影，松手后保存排序。
- 分段右侧仅在存在隐藏项时显示“添加 N”，用于恢复已移除小部件。
- 空态区分“没有可显示小部件”和“已有小部件被移除”，并给出“前往管理”或“添加小部件”。

### 6.2 工具列表

- 点按卡片：打开工具。
- 长按后不移动：打开菜单，可从工具页隐藏、停用插件或前往管理。
- 长按并拖动：显示落点虚影，松手后保存排序。
- 列表末尾显示隐藏数量，并提供“在管理中恢复”。
- 为读屏提供上移、下移、移到开头、移到末尾和隐藏等自定义动作。

以上是当前已验证的编辑方式。**显式编辑模式、常驻拖拽手柄、撤销栈、尺寸缩略图 sheet 和
编辑态隐藏开关不属于本设计基线**。未来若某个复杂场景确需批量编辑，应作为独立产品方案验证，
不得据旧版预览直接推广到主页和工具页。

### 6.3 管理摘要与详情

- 列表保持摘要；启用开关始终在摘要行，点按整行打开该插件的详情面板。
- 摘要使用“`v版本 · 工具页 · 主页`”“仅工具页”“仅主页”“已隐藏”“已停用”等用户语言。
- 关闭更新检查时，摘要也要显示“不检查更新”。
- 详情面板包含显示位置、真实权限范围、更新检查、插件包与数据维护，关闭后保留列表位置。
- 插件没有主页小部件时明确显示“此插件没有主页小部件”，避免用户误判为加载失败。
- 停用状态使用明确文字，正文保持可读；停用后仍可进入详情，导出或删除。

### 6.4 仓库和更新

- 仓库分为“已安装”和“可安装”。已安装卡直接显示当前版本走向，例如“1.5.0 → 1.6.0”。
- 版本选择放在溢出菜单，底部面板逐行说明升级、切换构建、降级或不兼容原因。
- 自动检查有更新时使用集中弹窗；“稍后”“本次不再提示”“全部更新”语义必须区分。
- 正式版不展示调试仓库；Debug 构建在设置的开发者选项中选择渠道。
- 首次进入仓库可提示插件权限风险，后续安装确认保持简短，不常驻展示签名／哈希等实现细节。

## 7. 宿主页模式

### 7.1 主页

页面主标题使用“工具台”，日期作为主色 eyebrow，工具和组件数量使用轻量摘要行，让实际小部件优先。
保持整块点按进入、长按后不移动弹出原位小菜单、长按并拖动排序，不新增独立编辑模式。

### 7.2 工具

内容区显示“全部工具”，并用一行简短说明“点击打开 · 长按拖动排序或调整”。工具卡包含图标底座、名称、右侧版本和
最多三行描述；整卡可点按，不再给版本做伪按钮。

### 7.3 管理

先给一句职责说明，再展示“已安装插件”；只有宿主未来确有不可外置的可选系统工具时才增加对应
分段，不为空分段绘制占位卡。Shizuku 授权与其他工具一样以外部插件呈现。列表摘要可扫，
点按后在对象详情面板处理从属设置。普通插件只显示需要用户决定的权限、范围和允许开关；插件自己的
私有数据空间属于运行基础，不列入权限管理。数据管理提供“导出数据／导入数据／清除数据”，与插件包本身的
导出和删除分开命名。完全信任的系统插件仍使用与其他插件一致的“工具页／主页”摘要，并追加“完全信任”；
详情中用用户语言说明它可直接使用本应用拥有的系统权限、无法逐项限制。其他普通插件使用其提供的系统功能时，
仍按普通插件自己的权限设置检查。页面不再跳转到独立“界面管理”。

### 7.4 仓库

先显示可选的应用更新卡，再显示“已安装”和“可安装”。刷新属于“已安装”分段动作；
“全部更新”仅在有更新时出现；“导入本地插件包”放在列表末尾作为满宽次要动作。

### 7.5 设置与关于

设置按“外观／更新／备份与迁移／开发者选项（Debug）／关于”分组。关于使用标准返回顶栏，
顶部居中展示应用身份，下方以单组设置行列出版本、SDK、构建、项目和许可；版本行必须说明可以
长按复制完整版本串。

“备份与迁移”只展示数据包导出、数据包导入和插件数据删除；统一导入兼容旧格式，
不再并列展示三个看似等价的迁移入口。三个入口使用普通设置行配色，不显示实现阶段或技术说明。
导入、导出、删除统一使用全屏两步任务界面：选择内容 → 确认操作。标题、步骤和底栏固定，
软键盘弹出时底栏保持可见，收起后恢复完整页面高度；尺寸计算不得受弹窗自身缩小后的高度限制。
中间列表独立滚动；不使用可拖动关闭的底部面板，也不因点击外部退出。返回确认页的上一步时保留选择与滚动位置，
已有选择修改或已填写密码时，关闭需要确认放弃。手机全屏、宽屏内容最大 720 dp，并处理系统栏与软键盘 inset。
导出按应用／插件分组，逐项选择不导出／明文／加密；导入根据数据实际支持的方式呈现跳过、导入、替换或合并。
确认页按对象列出所选数据和处理方式，需要密码时在此输入；敏感明文和替换现有数据明确警告。
删除使用同样的分组选择与核对流程，确认页须勾选永久删除声明，最后才允许执行。依赖联动和底层校验保持有效。

## 8. 插件页面指导

### 8.1 接入方式

- Runtime v2 页面统一从 `ui/*.json` 声明式入口启动；简单页面使用 `column` 根节点，由宿主直接渲染共享 Compose 组件；
- 复杂页面使用 `webview` 根节点选择 WebView renderer，并只消费宿主注入的 `--ats-*` CSS token，不复制色板或类型层级；正文、标题、标签和按钮分别使用对应的 `--ats-type-*` 字号、行高与字重，不继承浏览器默认值；
- 宿主私有 Compose 页面与 trusted-provider 共享 UI 继续使用公开设计 token；普通插件只使用 format v3 Host/WebView 声明入口。
- 页面优先复用 SDK 的 `SuiteCard`、`SectionHeader`、`EmptyState`、`LoadingState`、
  `ErrorState`、`DismissibleNotice`、`SuiteStatusChip` 和设置行组件。
- 不复制颜色、间距、圆角或浅色专用 View 工具；`UiKit.java` 已废弃，不用于新页面。
- 插件详情顶栏由宿主提供，插件根内容不要再添加返回按钮或应用级标题栏。
- Host renderer 使用契约提供的共享 Material 图标；WebView 当前只注入主题 CSS，没有共享图标资源端点，刷新等操作使用明确文字按钮，不用“辅”“✓”“♥”“↻”等字符模拟功能图标。

两个 Web 插件的内容区首行呈现本地数据摘要和刷新，Phigros 同时提供账号管理入口；抽卡账号使用横向选择标签，业务页签
沿用下划线选中态，两个插件的四个主标签均分整行，指示器宽度与每个标签同步，不挤在左侧。
抽卡概览使用总览统计、横向卡池选择和当前卡池时间线；
Phigros 使用合并的玩家／RKS 摘要、四列难度统计与紧凑成绩字段卡。抽卡记录每页
50 条，Phigros 成绩与定数每页 40 项；搜索／筛选作用于完整数据，换页只改变可见项。
加载结束应恢复按钮原有可用状态，不能启用缺少账号、链接或成绩数据的动作。

Phigros 使用“总览／成绩／时间线／定数表”四个业务入口；成绩内切换 RKS 列表与 B30，
账号管理从内容区头部打开独立对话面板，保留服务器选择、TapTap 登录、手动令牌、备注与删除范围说明。
总览显示真实本地历史的 RKS 变化图，时间范围为 7 天／30 天／90 天／全部，默认 30 天；
坐标随数据范围调整，空历史、单点和下降均如实显示，不从当前 RKS 反推历史。
难度统计按 EZ／HD／IN／AT 分列，逐项显示 Clear、FC、AP，不合计三种状态推算有效成绩。
总览不放 B30 或推分目标快捷卡，B30 保留生成成绩图入口；分组已由 P3/B27 标题说明，卡片仅显示一次序号。
RKS 和定数表直接显示 EZ／HD／IN／AT 多选按钮，默认 IN、AT，不设置“全部”或单独筛选面板。
搜索后保留全局 RKS 排名。定数表沿用迁移前的整数定数分组，行内依次为定数、曲名及作曲者（或 ID）、难度；
组内按定数降序，再按曲名排序，保留 40 条分页以控制 WebView 开销。
同步期间仍能浏览本地页面、筛选和历史，写入和重复提交操作继续受忙碌状态限制。
抽卡分析设置按账号保存，目标星级时间线使用可展开详情；Phigros 图片先预览，再由用户选择保存位置。

两个 Web 插件的短暂操作结果使用固定在当前视口底部的 Snackbar，可手动关闭；普通反馈
5 秒后消失，错误反馈保留 10 秒，长任务的新进度会刷新计时，不把反馈永久留在页面顶部。
提示使用统一的反色表面和文字（Web 分别取 `--ats-on-surface` / `--ats-surface`），不使用左侧
色条或绿色底块；错误以具体文案和 alert 语义反馈，普通结果使用 status 语义。
Phigros 使用迁移前插件自己的深／浅难度与评级色；个人简介保留原始换行，窄屏资料分行，
推分 ACC 与单曲 RKS 采用带分隔线的独立字段，不能紧贴拼成一句。
时间线节点默认折叠，摘要只呈现日期、RKS 和变化数量，点开节点后再显示成绩变化。
抽卡获取页将链接输入、就绪状态和“获取新记录”置于同一卡片；同卡提供次要操作“刷新全部记录”，
说明该操作重新读取当前链接账号所有卡池的接口可见历史并合并，不删除本地记录。粘贴后可直接获取，日志／角色
获得链接后滚动回该卡片。设备日志默认搜索系统仍保留的全部时间，可选择较短范围；米游社
不提供 Cookie 高级备用输入，扫码可取消，退出需要确认。长曲名不得撑宽整个页面。
获取完成后保留本次打开期间的链接并停留在操作页，显示新增／检查数量和账号，提供“查看记录”；
不自动清空链接，也不把凭据写入持久存储。运行进度在同一卡片内反馈，轻量结果仍用 Snackbar。

抽卡获取入口按“粘贴链接／设备日志／米游社”组织，只展示所选方式。日志或角色取得链接后，
返回链接操作区继续获取；完整刷新放在同卡的次要说明中，仍读取接口可见历史并与本地合并。
概览优先显示客观计数，欧非评价收进说明；保留横向账号条和卡池摘要，点击卡池更新详情并保留横向位置。
UIGF 导入先展示各游戏的新增／重复记录数量，用户确认后才写入；失败按游戏说明已完成部分。
删除数据保留独立确认并按游戏划分，不与导入导出并列突出。

Shizuku 授权页先显示连接状态，再呈现启动、授权、连接三步；按当前状态显示主要动作，并提供重新检查。
完全信任说明保持可见，不把普通插件权限与系统授权混在一起。
无障碍授权把自动启用与搜索／收藏筛选分开，组件名收进服务详情；说明开启自动启用后新收藏服务也会被启用。

两个 Web 插件的标签页与宿主分区采用相同的导航意图：横向跟手拖动、约 30% 页宽阈值或明确
快速滑动切换，短拖回弹；点按标签也使用横向过渡，指示器跟随移动。头部和标签固定，内容页
独立纵向滚动，返回时保留位置。只预加载相邻页，非当前页不可交互；输入框、弹窗和页内横向
卡池等滚动区域优先处理自己的手势。首尾不循环，减少动画设置下直接完成切换。

### 8.2 内容层级

推荐顺序是：

1. 必要的账号／数据源选择；
2. 当前关键结果或状态摘要；
3. 页签或筛选；
4. 详情卡片；
5. 导入、导出、删除等维护动作。

同一页不要同时用大标题、强调卡、彩色数值和多个主按钮争夺焦点。统计卡中的颜色要有标签，
例如“UP”“歪”“推分 ACC”，不能只用绿／红区分。

### 8.3 插件自有颜色

插件可为稀有度、难度或品牌维护领域色。使用 `SuiteTheming.isDark` 选择深浅档；如果该颜色表达
成功、警告、危险或信息，应直接改用 `SuiteSemantic.current`。领域色与背景的对比度不足时，
优先增加文字、形状或图标，而不是继续提高饱和度。

### 8.4 敏感信息和风险文案

- 不显示或记录 SessionToken、AuthKey、Cookie 等完整凭据。
- 说明实际数据范围和后果，例如“仅在本机加密保存”“不写入数据库”“导入只合并新记录”。
- 用户界面使用“应用”“插件”“版本”等用户词汇；`宿主`、`versionCode`、`同一进程`、
  `索引签名` 等实现词只在确实帮助诊断的关于页或开发文档中出现。

## 9. 无障碍与可用性

- 所有图标按钮提供动作含义；纯装饰图标的 `contentDescription` 设为 `null`。
- 整行点击与行内 Switch／菜单必须各自可操作，不留下内边距死区。
- 最小触摸目标遵循 Material 组件默认值，紧凑视觉不等于缩小命中区域。
- 拖拽必须同时提供读屏自定义动作；颜色信息必须有文字或图标冗余。
- 文本允许系统字号放大，卡片标题和尾部状态应能换行或省略，不依赖固定像素宽度。
- 浅色、深色、动态取色、竖屏、横屏、手机、宽屏和 TalkBack 都属于发布前检查范围。

## 10. 文案规则

| 不推荐 | 推荐 | 原因 |
| --- | --- | --- |
| 要求宿主 `versionCode ≥ 18` | 需要应用 1.5.0 或更高版本 | 给用户可理解的版本与解决方向 |
| 3 个内置 · 1 个外部 | 4 个工具已就绪 | 不暴露实现分类 |
| 仓库索引签名验证成功 | 已验证发布 | 保留结果，不展示机制 |
| 操作失败 | 仓库刷新失败：网络连接超时 | 说明对象和原因 |
| 确定 | 删除插件／全部更新／重新安装 | 按钮表达实际后果 |

文案优先回答“现在是什么状态”“我能做什么”“操作会影响什么”。安全风险和数据范围不能为了
简短而省略，但应写成用户后果，不写架构自述。

## 11. 不再采用的旧方案

以下内容曾出现在旧版计划或预览中，但没有成为现行设计，后续不应把它们当成待办：

- 四项底栏加顶栏设置齿轮；现行是五个一级入口，设置位于底栏／侧栏。
- 每个一级页都显示顶栏标题；现行一级页避免重复顶栏，只有详情和关于使用返回顶栏。
- 主页与工具进入显式编辑模式，显示拖拽手柄、移除角标、撤销栈和尺寸缩略图 sheet。
- 工具编辑态使用常驻可见性开关。
- 把导出和删除完全移出管理页；现行管理展开区保留快捷操作，仓库仍是版本与安装生命周期主入口。

保留的设计成果包括：统一 token、品牌／动态配色、五个一级分区、管理摘要卡、两段式仓库、
设置与关于、标准详情顶栏、静默自动检查、Snackbar／局部进度、共享状态组件、宽屏边界、
落点虚影和读屏重排动作。

## 12. 评审清单

新增或修改宿主／插件 UI 时至少核对：

- [ ] 页面职责符合五个一级入口和二级页面边界；
- [ ] 使用 SDK token 与共享组件，没有新增近似颜色、间距或圆角；
- [ ] 浅色、深色和动态取色下前景／容器配对正确；
- [ ] 页面只有一个主要视觉焦点和一个明确主动作；
- [ ] 空、加载、失败、禁用、处理中和完成状态均有设计；
- [ ] 主动操作有反馈，后台无结果不会产生噪音；
- [ ] 高风险动作写明后果并在需要时确认；
- [ ] 图标、Switch、菜单、拖拽和自定义动作可被读屏使用；
- [ ] 手机与 `>= 840 dp` 宽屏布局均正确，内容不超过 `720 dp`；
- [ ] 文案使用用户语言，不泄露凭据，不用实现术语替代说明；
- [ ] HTML 样例、本规范和实际 Compose 实现没有互相矛盾。

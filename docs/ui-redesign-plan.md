# Android Tool Suite 界面与交互重设计方案

本文覆盖宿主应用、`plugin-sdk` 设计系统与三个插件的界面改动。方案基于四条使用反馈，
并合并了此前对现有 UI 的问题排查结论。

预览文件：[ui-redesign-preview.html](ui-redesign-preview.html)（浏览器打开，可切换浅色／深色）。

## 1. 设计目标

| 目标 | 现状问题 | 处理方向 |
| --- | --- | --- |
| 更新提示不打扰 | 启动自动检查后常驻一条不可关闭的状态横幅，无更新时也占位 | 无更新完全静默；有更新才弹窗；自动检查可关 |
| 一件事只在一个地方做 | 插件管理／界面管理／插件仓库三屏职责交叉 | 按"调行为"与"装卸载"两类意图重新切分 |
| 设置有归属 | 没有设置入口，版本号在界面上完全查不到 | 新增设置屏，内含关于、更新、备份、外观 |
| 文案讲人话 | 大量"宿主""同一进程""versionCode""索引签名"等实现术语 | 删除实现细节，安全提示改写为用户视角 |
| 视觉一致 | 圆角 8/16/18/20/22/24 混用，语义色各插件硬编码 | 收敛到 SDK token，插件不再自造 |
| 编辑不误触 | 拖拽常驻激活，长按语义重载，无撤销，读屏无法重排 | 显式编辑模式 + 可见手柄 + 撤销栈 |
| 插件多了仍可扫 | 管理屏每插件 3 个开关平铺，8 个插件就是一屏墙 | 逐项收起，摘要行交代完整状态 |

## 2. 信息架构

改动前（3 个底栏项 + 2 个用布尔标志切换的子屏）：

```
主页
工具
管理 ─┬─ 界面管理（每插件：工具页/主页可见性）
      └─ 插件仓库（渠道切换、刷新、全部更新、导入本地包）
      · 管理屏本体：仓库入口、导入、界面管理入口、检查更新、
        导出/导入迁移包、状态横幅、2 条常驻说明、
        内置插件开关、外部插件开关 + 导出/删除
```

改动后（4 个底栏项 + 顶栏设置入口）：

```
主页        小部件网格
工具        工具列表（点击进入，拖动排序）
管理        每个插件一张卡：启用开关 + 工具页可见 + 主页可见
仓库        已安装（更新/导出/删除） + 可安装（浏览/安装） + 导入本地包
设置        外观 / 更新 / 备份与迁移 / 开发者选项(debug) / 关于
 └─ 关于    版本、SDK 版本、构建信息、开源地址、许可
```

切分依据是用户意图，不是数据来源：

- **管理**回答"我装的插件怎么表现"——启用、在哪儿显示。这是会反复调的地方。
- **仓库**回答"我要装什么、卸什么"——获取、更新、移除、导出包。生命周期操作。
- **迁移包**是整机级备份，不属于单个插件，移入设置。

"已安装／可安装"两段式仓库是应用商店的通用范式，同一插件出现在管理和仓库两处不会
造成困惑，因为两处的动作互不重叠。

底栏 4 项在 Material 3 的 3～5 项区间内。设置放顶栏齿轮而非底栏，避免把低频入口
提到和高频并列。仓库项在有可用更新时显示红点角标。

## 3. 逐屏设计

### 3.1 主页

保留小部件网格与拖拽重排。改动：

- 顶部摘要从"3 个内置 · 1 个外部 · 4 个主页组件"改为"4 个工具 · 4 个主页组件"。
  内置／外部是实现区分，用户不需要知道。
- 分区副标题"拖动时虚影预览落点；长按后松开可调整或隐藏"改为"长按调整大小或隐藏"。
- 新增顶栏（应用名 + 设置齿轮），取代现在无顶栏、标题直接写在滚动内容里的做法。
- 空态文案"可在插件管理的界面管理中重新显示小部件"改为"在管理中开启插件的主页显示"，
  并附一个直接跳转按钮。

### 3.2 工具

- 副标题"点击打开；拖动时虚影预览落点，松手后保存排序"改为"拖动可调整顺序"。
- 卡片上的版本号从可点击的 `AssistChip` 改为普通标签。它现在的点击行为和整卡重复，
  而 chip 的视觉暗示了一个不存在的独立操作。
- 图标补 `contentDescription`，它是卡片上唯一的类型信号。

### 3.3 管理（合并界面管理，可展开收起）

每个插件一行，**默认收起**。收起态用一行摘要交代完整状态，不必展开就能扫完整屏：

```
┌────────────────────────────────────────┐
│ 🎲  抽卡分析                            │
│     v1.6.0 · 工具页 · 主页    [ ● ]  ⌄ │   ← 收起
└────────────────────────────────────────┘
┌────────────────────────────────────────┐
│ 🎵  Phigros Data Studio                 │
│     v2.2.0 · 仅工具页         [ ● ]  ⌃ │   ← 展开
│ ────────────────────────────────────── │
│     在工具页显示                 [ ● ] │
│     在主页显示                   [ ○ ] │
└────────────────────────────────────────┘
┌────────────────────────────────────────┐
│ 📋  剪贴板历史                          │
│     v1.0.0 · 已停用           [ ○ ]  ⌄ │   ← 停用，整行降低不透明度
└────────────────────────────────────────┘
```

摘要行的取值覆盖全部状态组合，这是这个设计成立的前提——如果必须展开才知道状态，
收起就只是把问题藏起来：

| 状态 | 摘要 |
| --- | --- |
| 启用，工具页 + 主页都显示 | `v1.6.0 · 工具页 · 主页` |
| 启用，只在工具页 | `v1.6.0 · 仅工具页` |
| 启用，只在主页 | `v1.6.0 · 仅主页` |
| 启用，两处都隐藏 | `v1.6.0 · 已隐藏` |
| 停用 | `v1.6.0 · 已停用`（整行 62% 不透明度） |

交互细节：

- **启用开关留在收起行上**，不放进展开区。启用／停用是这屏最高频的单个动作，
  不该为它多一次点击。行主体点击展开，开关自己是独立点击目标，两者都 ≥48 dp。
- 展开区只放两个可见性开关。关闭"启用插件"时展开区自动折叠并置灰——从属关系用状态
  表达，不写文字解释。
- 没有主页小部件的插件，"在主页显示"整行不渲染，摘要里也不出现"主页"。现在的做法是
  渲染成禁用态，会让人以为是权限问题。
- 允许多行同时展开，不做手风琴（关掉别人的卡片会让人意外）。展开状态不持久化，
  每次进入这屏都是全收起。
- 内置与外部分两段，段标题"系统工具"／"已安装插件 · N 个"，去掉"可选能力可按需停用"
  这类解释性副标题。
- 删除页内的"导出／删除"按钮（移到仓库屏）和两条常驻说明横幅（见 §5）。

### 3.4 仓库（合并导入／导出／删除）

两段结构：

**已安装** — 每张卡显示当前版本，有更新时显示"更新到 vX.Y.Z"主按钮，
溢出菜单（⋮）内放"导出插件包""删除"。删除走二次确认对话框。

**可安装** — 未安装的仓库插件，主按钮"安装"。版本选择器保留但收进溢出菜单，
默认直接装最新版；降级／指定版本是低频高风险操作，不该占主按钮位置。

底部固定"导入本地插件包"次要按钮。

其他改动：

- 渠道切换（正式／调试仓库）移入设置的开发者选项，且仅 debug 构建可见。
  release 构建里暴露"调试仓库"是在向用户展示内部发布流程。
- "全部更新"保留在段头右侧。
- 不兼容插件的提示从"要求宿主 versionCode ≥ 18"改为"需要应用 1.5.0 或更高版本"，
  并直接给"更新应用"按钮。
- 验证状态从一整行文字压缩为标题旁的 ✓ 图标 + tooltip。
- 删除两条关于进程模型与签名机制的常驻说明；安装类风险提示改为首次进入仓库时的
  一次性对话框，之后仅在安装确认弹窗里以一行短句出现。

### 3.5 设置（新增）

标准 M3 列表分组，不用卡片堆叠：

```
外观
  主题                    跟随系统 ▾
  配色                    默认配色 ▾

更新
  自动检查更新                 [ ● ]
  立即检查更新
  上次检查  今天 14:32

备份与迁移
  导出迁移包
  导入迁移包
  包含布局与插件包，不含账号与插件数据

开发者选项                      （仅 debug 构建）
  插件仓库渠道            正式仓库 ▾

关于
  安卓工具合集  1.4.0            >
```

- **主题**：跟随系统／浅色／深色。
- **配色**：默认配色／跟随壁纸。默认为应用自带配色。当前代码 `dynamicColor = true` 让
  Android 12+ 上品牌 teal 永远不出现，配色由壁纸决定，而启动图标仍是写死的 `#0F766E`，
  两者对不上。默认改为品牌色，动态取色降为可选。
- **自动检查更新**开关持久化到 `uiPreferences`，新增 key `auto_check_updates`，默认开。
- **上次检查**是只读时间戳，替代原来的常驻状态横幅。
- 迁移包那行说明是唯一保留的实现相关文案，因为它直接影响用户对备份范围的预期——但
  从原文"迁移包只包含宿主布局、仓库选择和插件包，不包含账号凭据或插件业务数据"压缩掉
  了"宿主""仓库选择"这些内部概念。

### 3.6 关于（设置的子屏）

```
        ┌────────┐
        │  图标  │
        └────────┘
       安卓工具合集
         1.4.0

版本号          1.4.0 (14)
插件 SDK        1.2.0
构建类型        release
项目地址        github.com/android-tool-suite   >
开源许可                                        >
```

版本行长按复制完整版本串，方便反馈问题时提供。`versionCode`、SDK 版本这类信息放在
这里是合适的——用户主动进入关于页就是来找这些的，和把它们混在功能界面里性质不同。

### 3.7 插件详情页

- 悬浮在左下角的返回按钮改为标准顶栏：返回箭头 + 插件名 + 溢出菜单。
  现在这个按钮没有导航栏 inset，可能和手势条重叠。
- 修掉重复的状态栏 inset（`Scaffold` 已给过 padding，内层又加了一次）。
- 顶栏溢出菜单放"在管理中设置""删除插件"，让详情页也能直达相关操作。

## 3.8 编辑交互重做（主页与工具）

### 现状问题

两屏共用 `dropPreviewReorder`，拖拽**始终处于激活状态**：任何长按加移动都会进入重排。
由此产生一串连锁问题：

1. 滚动过程中容易误触发重排。
2. 为了防止小部件内容抢走手势，`WidgetTile` 在插件视图上盖了一层吞掉所有 pointer
   事件的透明 `Box`（`HostAppUi.kt:528`），小部件内部因此完全不可交互，对 TalkBack
   也不可见。
3. 长按语义重载：按住不动出尺寸菜单，按住并移动进入拖拽，两个动作起手完全相同。
4. `dropPreviewReorder` 自己重写了 click / long-press 判定（`HostAppUi.kt:583`），
   绕开 `Modifier.clickable`，因此没有 ripple、没有焦点、没有最小触摸目标保证。
5. 没有撤销。拖错了只能再拖回去。
6. 键盘和读屏完全无法重排。

### 改为显式编辑模式

**进入**：长按任意小部件／工具卡 → 同时进入编辑模式并**立刻拿起**被长按的那一项。
手指已经在上面，可以直接拖，不需要先切模式再重新按一次。这也是 iOS 和 Android
桌面的通用手势。顶栏"编辑"按钮作为可发现的第二入口。

**退出**：顶栏"完成"、系统返回键、或点空白区域。

编辑模式下顶栏换成：`← 编辑主页    ↺撤销    完成`

```
非编辑态                          编辑态
┌──────────────────┐             ┌──────────────────┐
│ 安卓工具合集   ⚙ │             │ ← 编辑主页  ↺  完成│
├──────────────────┤             ├──────────────────┤
│ 8月11日 星期二    │             │ 拖动排列 · 点击改尺寸│
│ 工具台            │             ├──────────────────┤
│                  │             │ ┌────┐  ┌────┐   │
│ ┌────┐  ┌────┐   │             │ │ ⊖  │  │ ⊖  │   │
│ │Shiz│  │无障碍│   │   长按    │ │Shiz│  │无障碍│   │
│ └────┘  └────┘   │   ──────> │ │  ⋮⋮│  │  ⋮⋮│   │
│ ┌────┐  ┌────┐   │             │ └────┘  └────┘   │
│ │Phig│  │抽卡 │   │             │ ┌────┐  ┌ ─ ─ ┐ │
│ └────┘  └────┘   │             │ │Phig│  │  ＋  │ │
│                  │             │ └────┘  └ ─ ─ ┘ │
└──────────────────┘             └──────────────────┘
```

编辑态下每个小部件获得三个可见附件：

- 左上角 `⊖` 从主页移除（写入 `PREF_HIDDEN_WIDGETS`，和现在的"不在主页显示"同一个偏好）。
- 右下角 `⋮⋮` 拖拽手柄。手柄之外的区域仍可滚动，解决误触发。
- 整块点击 → 底部弹出尺寸选择（见下）。取代现在藏在长按菜单里的尺寸项。

末尾多一个虚线 `＋ 添加小部件` 格子，点击弹出已隐藏小部件列表。**现在要把隐藏的小部件
找回来，必须走"管理 › 界面管理 › 找到插件 › 主页开关"**，这是整个应用里最绕的一条路径。

### 尺寸选择

现在是 `DropdownMenu` 里一串"尺寸 2×2""尺寸 4×2"文字项，读不出实际效果。
改成底部 sheet，用等比缩略图直观呈现：

```
┌────────────────────────────────┐
│ 无障碍授权                      │
│                                │
│  ┌──┐      ┌──────┐            │
│  │▪▪│      │ ▪▪▪▪ │            │
│  └──┘      └──────┘            │
│  2×2 ✓      4×2                │
│                                │
│         从主页移除              │
└────────────────────────────────┘
```

只渲染该小部件 `supportedSizes()` 声明的尺寸，选中项打勾。

### 工具页编辑态

同一套手势。编辑态下每行获得拖拽手柄和一个可见性开关：

```
┌────────────────────────────────┐
│ ⋮⋮  🛡  Shizuku 授权     [ ● ] │
│ ⋮⋮  ♿  无障碍授权        [ ● ] │
│ ⋮⋮  🎵  Phigros          [ ● ] │
│ ⋮⋮  🎲  抽卡分析         [ ○ ] │  ← 隐藏，行内容降透明度
└────────────────────────────────┘
```

这个开关写的是 `PREF_HIDDEN_TOOLS`，和管理屏"在工具页显示"是同一个偏好。同一个设置在
两处出现是有意的——用户在工具页看到不想要的条目时，就地隐藏比跳去管理屏更直接
（类似 iOS 既能在桌面删应用也能在设置里删）。编辑态**不含**启用／停用，那是管理屏的
职责，避免在工具页误停用插件。

### 撤销

编辑模式内维护一个操作栈（重排、改尺寸、移除、隐藏），顶栏 `↺` 逐步回退。
退出编辑模式时清空。这是目前完全缺失的安全网。

### 无障碍

编辑态下手柄和开关都是真实可聚焦控件，读屏和键盘天然可用。每一项补
`semantics { customActions }`：上移／下移／移到开头／移到末尾／移除。
拖拽手势改为叠在 `Modifier.clickable` 之上而不是取代它，恢复 ripple、焦点与
最小触摸目标。

同时**移除 `WidgetTile` 上那层吞事件的透明 `Box`**：非编辑态下小部件不再需要为拖拽
保留手势，整块交给 `clickable` 打开插件即可；编辑态下手势只在手柄上。

## 4. 更新检查流程重设计

现状：`onStart()` 调 `checkForUpdates(false)`，结果写入 `updateStatus` 字符串，
在管理屏和仓库屏各渲染一条常驻 `Notice`。严重性靠 `startsWith("检查更新失败")`
字符串前缀匹配判定。无更新时同样占一行"已是最新版本"。

### 新流程

| 触发 | 有更新 | 无更新 | 失败 |
| --- | --- | --- | --- |
| 启动自动检查（开关开） | 弹窗 | **完全静默** | **完全静默** |
| 设置里手动检查 | 弹窗 | Snackbar「已是最新版本」 | Snackbar「检查失败：<原因>」+ 重试 |
| 仓库屏下拉刷新 | 列表就地更新 + 角标 | 列表就地更新 | 段头内联错误行 + 重试 |

自动检查失败静默，是因为用户没有主动发起这个动作，网络波动不该产生噪音。
手动检查必须有反馈，否则按了没反应。

### 更新弹窗

```
┌────────────────────────────────┐
│ 发现 3 项更新                   │
│                                │
│ 安卓工具合集   1.4.0 → 1.5.0   │
│ 抽卡分析       1.6.0 → 1.7.0   │
│ Phigros       2.2.0 → 2.3.0    │
│                                │
│ 本次不再提示   稍后    全部更新 │
└────────────────────────────────┘
```

- 「全部更新」按顺序执行，进度显示在仓库屏对应卡片上，不阻塞弹窗。
- 「稍后」关闭，下次启动仍提示。
- 「本次不再提示」把这批版本号记入 `dismissed_update_versions`，直到出现更高版本才
  再弹。避免每次启动都被同一条更新拦住。
- 应用自身更新和插件更新混在一个弹窗里，因为对用户来说都是"有东西要更新"。

### 状态表达的替换

- 删除两屏的常驻 `updateStatus` 横幅。
- 引入 `UpdateCheckState` 枚举（`IDLE / CHECKING / UP_TO_DATE / AVAILABLE / FAILED`）
  替代字符串前缀匹配。

## 6. 设计系统改动（`plugin-sdk`）

这次重设计需要的最小 token 集，全部是新增，二进制兼容：

```kotlin
object SuiteSpacing {                    // 替掉散落的 2/5/6/7/9/13/18 等随机值
    val xs = 4.dp;  val sm = 8.dp;   val md = 12.dp
    val lg = 16.dp; val xl = 20.dp;  val xxl = 24.dp; val xxxl = 32.dp
    val ScreenPadding = 20.dp
    val ListGap = 12.dp
}

object SuiteShapes {                     // 替掉 8/16/18/20/22/24 混用
    val Card = RoundedCornerShape(24.dp)
    val Inner = RoundedCornerShape(16.dp)
    val Chip = RoundedCornerShape(12.dp)
    val Dialog = RoundedCornerShape(28.dp)
}

// 成对语义色，浅深两套，全部按 4.5:1 校验
val SuiteSemantic.success / onSuccess / successContainer
val SuiteSemantic.warning / onWarning / warningContainer
val SuiteSemantic.danger  / onDanger  / dangerContainer
val SuiteSemantic.info    / onInfo    / infoContainer

// 宿主可以钉死主题，插件不能读 isSystemInDarkTheme()，
// 所以由 SDK 暴露已解析的深浅状态，供插件给自己的调色板选档
val SuiteTheming.isDark
```

**游戏配色不进 SDK。** 稀有度、难度、评级配色属于单个插件的领域知识，SDK 作为宿主与插件之间的
公开契约不应该认识「5 星是金色」「IN 是紫色」这类规则。这些调色板留在各插件内部
（`GachaRarityPalette`、`PhigrosPalette`），各自维护浅深两档。跨插件共享的只有
`SuiteSemantic` 那四组语义色：UP/歪、RKS 涨跌、运气档位这类「好/一般/差」判断走语义色，
和宿主的成功/警告/危险保持一致。

新增组件：

- `SuiteTopBar` — 统一顶栏。现在应用里有三种返回形态（详情页悬浮按钮、子屏内联
  `IconButton` + 大标题、纯系统返回），全部收敂到这一个。
- `SuiteSettingsGroup` / `SuiteSettingsRow` / `SuiteSettingsSwitchRow` — 设置屏用。
- `LoadingState`（含骨架屏）／`ErrorState`（带重试）／`DismissibleNotice` — 补齐
  AGENTS.md 要求但 SDK 一直没提供的态。Phigros 现在自己写了个私有 `EmptyHint`，
  抽卡自己写了 `StatusNotice`，都是因为 SDK 缺件。
- `SuiteStatusChip` — 统一"已启用／未启用／已验证"这类徽章。

`SuiteTheme` 增加 `themePreference` 参数 + 进程内可观察的偏好持有器。这是设置屏
「主题／配色」能生效到插件的前提——插件通过 `composePluginView` 各自 new 一个
`SuiteTheme`，`AndroidView` 边界隔断了 CompositionLocal，必须有显式通道。

`pluginSdkVersion` 1.1.0 → 1.2.0，三个插件 `atsPluginSdkVersion` 同步。

`UiKit.java`（硬编码浅色的 View 工具集，仓库内 37 处引用全部位于 `MainActivity`
已不可达的方法中）打 `@Deprecated`，下个 SDK 大版本删除。它在公开 SDK 面上，
直接删会破坏第三方插件。

## 9. 已定决策

1. **底栏 4 项**（主页／工具／管理／仓库），设置走顶栏齿轮。仓库项承载更新角标。
2. **配色默认品牌 teal**，动态取色（跟随壁纸）降为设置里的可选项。
   现状 `dynamicColor = true` 让 Android 12+ 上品牌色永不出现，与写死 `#0F766E` 的
   启动图标对不上。
3. **渠道切换仅 debug 构建可见**，放设置 › 开发者选项。release 构建完全隐藏。
4. **管理屏逐项可展开收起**，收起态摘要覆盖全部状态组合，启用开关留在收起行上。
5. **主页与工具改显式编辑模式**，长按进入并立刻拿起，撤销栈 + 可见手柄 + 尺寸 sheet。
6. 阶段 1–5 为本次闭环，阶段 6（无障碍与 i18n）后置。编辑模式本身已把阶段 6 里
   拖拽无障碍那部分带出来了。
